# C05 first-route Rust engine

This standalone SDK package implements the reviewed Rust-provider ABI. It has no
MadB CLI, application, adapter, or other SDK dependency. The production C header
is generated by cbindgen from `src/lib.rs`; the C02 handwritten declarations
remain the independent shape baseline. `test-support.h` describes only the
separate, explicitly enabled fixture control surface.

The two required build inputs, `MADB_INTERFACE_DIGEST` and
`MADB_PROFILE_DIGEST`, are each exactly 64 hexadecimal characters without a
`sha256:` prefix. The generation pipeline supplies them from its fixed interface
and resolved profile; a missing or malformed identity fails the build. There is
no default identity and no candidate digest cycle. Bootstrap returns the 32 raw
interface bytes followed by the 32 profile bytes. Consumers must compare both
before creating resources or calling business functions.

```sh
# Supply the actual generated identities before building a candidate.
cargo build --manifest-path sdk/rust/engine/Cargo.toml --release --locked --offline
cargo test --manifest-path sdk/rust/engine/Cargo.toml --features test-support --locked --offline
```

The loaded SDK image owns one token namespace and registry, with at most
`MADB_MAX_HANDLES = 4096` engine/subscription registrations and
`MADB_MAX_SUBSCRIPTIONS_PER_ENGINE = 64` subscriptions per engine. Admission at
capacity returns ResourceExhausted before accepting a new resource or context.
Closed registrations retain their capacity slot until their caller releases the
token. Tokens increase monotonically and never wrap or get reused. This registry
is not a business-engine singleton or a shared executor.

`observe` synchronously publishes the initial snapshot `(sequence=1, state=0)`.
There is no timer, consumer queue, replay, or hidden worker. The test source can
publish later values through the same serialized source lease used by the
initial callback. Already admitted deliveries may complete after a close
request; successful `await_closed` proves every such source lease and callback
has exited. The caller retains context until that success. A concurrent source
attempt returns Busy; source recursion from that callback returns WouldDeadlock.

A single mutex serializes token lookup, type checks, operation/source admission,
and close state. Foreign callbacks execute outside it. The last actual permit or
source lease triggers pending drain. Closing an engine closes its subscriptions,
but their caller-owned tokens remain independently releasable. Native engine
payloads are actually dropped and borrowed callback/context fields revoked
before Closed is published. Native-only destruction has no fixed-thread
requirement and runs on the request/last-lease-returning thread; the profile does
not claim actor, environment, consumer-queue, or dedicated-thread execution.

No C pointer validity oracle is claimed. Non-null aligned outputs and accepted
input buffers must denote valid, disjoint allocations for the documented call
period. Callback/context may be invoked from the initial caller or the declared
serialized source; caller-owned context must permit those accesses. Foreign
exceptions/panics cannot unwind through a C callback. Rust panics inside exported
operations map to InternalFailure, with RAII returning acquired permits. A
poisoned registry returns InternalFailure and retains its resources rather than
claiming successful cleanup. Abort/OOM configurations do not promise recovery.

For `madb_fixture_bootstrap`, only non-null output with capacity exactly 64 is a
valid output region and is zeroed before checking version. Wrong output/capacity
returns InvalidArgument without writing; an unknown version with valid output
returns Unsupported and leaves 64 zero bytes.

The default Release exports exactly bootstrap, create, checksum, observe,
request_close, await_closed, and release_handle. The `test-support` feature adds
seven explicit fixture controls; it must receive a different resolved profile
identity and is not the uninstrumented Release candidate. Counters distinguish
actual native/context cleanup from registry-token removal. The fixture barriers
pause after real acquisition, and no second lifecycle state machine is used.
