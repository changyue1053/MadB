# Managed akinterop source for C07

This directory preserves three separately identified source patches for the CPF/akinterop route. They are mechanism-probe inputs, not a certified C07 profile, published SDK or complete installer.

| Source pin | Patch identity | Validated mechanism scope |
|---|---|---|
| [managed-source.json](managed-source.json) | `managed-akinterop-mainenv-r2` | Explicit reference ownership and finite generated-proxy notifications, including callback exceptions. Per-session drain leaves the env sentinel and TSFN alive. |
| [managed-source-r3.json](managed-source-r3.json) | `managed-akinterop-mainenv-r3` | Opt-in coordinated whole-runtime shutdown on the still-valid main env, after the finite producer/session has drained. This adds entry gating, hook removal, reference/metadata cleanup and native finalizer/context acknowledgment. |
| [managed-source-r4.json](managed-source-r4.json) | `managed-akinterop-mainenv-r4` | A single pre-init copied record codec, selected before generic class conversion, with actual KSP-declared Int32/string fields and typed notifications. Inherits r3 shutdown restrictions. |

Each source pin binds the same upstream Git commit and Kotlin source archive, exact original/patched files, patch bytes and upstream notices. r2 lists ten changed files; r3 lists thirteen; r4 lists fifteen. Apply each full patch to a new extraction of the pinned upstream commit, not on top of another patch. Verify every original file first and every resulting file afterward. Never modify a shared Maven/Gradle cache. The archive contains Kotlin runtime source; the native helper is separately sourced from the same Git revision. r2 patch and source-pin bytes retain their existing identity.

All three managed paths provide bounded explicit reference ownership, registered main-env/thread admission, owned nonblocking TSFN delivery, null-env payload disposal, registry cleanup and temporary argument release. r2 repairs indeterminate native call outputs on callback exceptions without changing the existing helper signatures. r3 retains that repair and adds an internal shutdown/metric ABI and opt-in runtime configuration. Rebuild the helper, cinterop, runtime, KSP exports and consumer together; ABI compatibility is not permission to mix patch identities.

The native helper uses locked formal application SDK headers; Kotlin cinterop/runtime use separately locked CPF platform headers/klib. The bridge ABI comparison, LLVM/sysroot identity and exact shared-link startup-object correction belong in the toolchain recipe, not this source pin. Source replay, matched Release builds and API23 Release emulator experiments with the formal SDK26 application toolchain are recorded in [the C07 review](../../../docs/reviews/2026-10-25-c07-arkts.md). Their evidence is specific to each patch and consumer; prior r1/r2 results are not relabeled as r3.

r3's `managedShutdownGlobalsOnly` is an internal experimental subset. Real interface creators remain necessary for generated outbound proxies; their NAPI constructor references are separately counted and released alongside descriptors. Concrete Kotlin classes, suspend/Promise exports, function binders and FFI constructor registrations are excluded before their separate owners are acquired. Non-global generated entries reject before reading callback data; all generated entries reject after closing before dereferencing released descriptors. This is not general object/Promise support.

The probe/control caller must first verify source/session drain, including producer completion, consumed termination-request Future, logical pending/depth zero and explicit session close. The runtime itself checks generated entry leases and accepted native payloads; it has no general source-owner registry. The probe control rejects unmet source prerequisites, and the runtime rejects active entry/payload ownership, with Busy while leaving the runtime open for ordinary drain. This does not implement a full engine's automatic close under queue saturation. An accepted request closes admission, explicitly removes the three registered hooks, releases references including the sentinel and interface metadata, and releases the TSFN. Its read-only acknowledgment requires balanced ownership and actual TSFN finalizer/context destruction, not just release-request success. Reference, descriptor and class-reference shutdown counters are final snapshots; live pre-close evidence comes from the corresponding managed audits. Consuming the Kotlin Worker termination Future is a producer/termination-request acknowledgment, not proof of pthread join or TLS destruction.

Explicit hook removal is distinct from the platform invoking an env cleanup hook. r3's quiescent experiment does not prove host-VM destruction, pending managed null-env disposal during early env exit, arbitrary unload or process-kill cleanup. A null ArkTS env does not itself mean the Kotlin/Native runtime is dead: pure K/N disposal additionally requires a live K/N runtime, valid interop entry and retained DSO/closure owners. The native null-env branch never calls N-API or user code.

The managed limits remain 128 owned references and 32 pending notifications. They do not establish the final SDK's payload/operation/waiter budgets. Full state/event behavior, byte saturation, business discard accounting, bootstrap-before-resource admission and complete candidate/Lab certification remain separate C07 work. In particular, disposing an abandoned closure does not execute its business `finally` block or automatically return a logical delivery ticket.

No downloaded source tree, native binary, cache or signing material is distributed here. [ATTRIBUTION.md](ATTRIBUTION.md) identifies the shared source notices and distinct local modifications.

## r4 copied-record scope

The fixed r4 patch selects one exact KClass before initialization, checks its real metadata, and skips native class/instance ownership only for that copied record. Input properties are read once; finite integral Int32, surrogate pairing, the 1,024 UTF-8 byte limit and explicit-length NUL are checked. Output uses own data-property definitions, never inherited setters. Narrow codec errors return through the global entry as recoverable NAPI errors while preserving an already-pending getter exception. This does not turn every Kotlin exception or entrypoint into a recoverable boundary.

The independent KSP processor reads actual annotated symbols; renamed-field generation and a source-located unsupported Long rejection were executed. Its fixed source/build/classpath identities and the Release/obfuscated API23 target result are linked in [the r4 observation](../../../docs/reviews/c07-r4-record-observation.json). The consumed processor-byte supplement corrects an empty cache-scan field in the original receipt; public compiler/dependency acquisition is still separate. This directory does not yet ship a complete standalone generator project.

The tested notification signature converts the fallible record before acquiring its final owned observer. Upstream arbitrary multi-argument conversion has no complete rollback transaction; a future generator must reject unsafe ordering or implement explicit rollback. No such general guarantee is inferred. The target passed 9 valid and 28 negative/getter cases, actual callback throw/recovery and balanced explicit whole-runtime shutdown. It did not destroy the main env or prove physical Kotlin worker/TLS join, a full Engine, or identity-before-resource bootstrap.
