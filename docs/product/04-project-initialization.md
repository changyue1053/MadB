# MadB 跨端工程一键初始化

MadB 增加工程初始化能力：开发者选择模板和目标平台，一次操作得到带示例功能、跨语言绑定、构建接线和 IDE 入口的完整工程。初始化后，开发者修改共享代码，再在对应 IDE 中构建或运行即可看到结果。

本功能扩展现有 `madb init`，属于待实施产品规范。当前文档没有交付可执行 CLI 或可安装 IDE 插件。实现边界见[架构设计](../architecture/14-project-initialization.md)，完成条件见[独立验收](../validation/06-project-initialization.md)。

## 1 用户体验

### 一条命令创建

下面是目标命令语法。`kmp-rust-app` 默认创建 Android 和 iOS 工程；在满足其固定工具链要求的 macOS 上运行：

```sh
madb init --template kmp-rust-app --out ./MyApp --open android-studio
```

工具完成模板解析、环境检查、目录生成、依赖锁定、绑定生成和目标构建，并打开 Android Studio。输出同时给出 Xcode 工程入口。后续不需要手动复制 `.so`、Framework、头文件或绑定源码。

目标平台可以显式选择：

```sh
madb init --template kmp-rust-app --out ./MyApp --targets android,ios
```

加入鸿蒙使用经过独立验证的组合配置；以下名称是设计中的模板配置名，其发布取决于对应工具链与集成验收：

```sh
madb init --template kmp-rust-app --out ./MyApp \
  --targets android,ios,ohos --profile mobile-ohos
```

此处 `--profile` 是 template profile，选择模块与工具链组合；它引用具体 boundary profiles，不等于路线 ID。`ohos` 表示目标族；模板配置必须进一步确定 HarmonyOS 或 OpenHarmony SDK、版本、ABI 和设备，不能把两者视为同一个已验证环境。模板没有匹配的组合配置时直接解释缺口，不擅自换桥接后端或删减目标。

开发者主要选择应用或 SDK、目标平台、已有接口和交付需求，不需要自行排列 FFI 工具。MadB 根据这些输入选择已受检的完整配置；需要跨机器发布的 SDK、源码共同构建的应用，以及反向宿主调用，可能使用不同配方。实验后端需显式选择，不能混入普通推荐模板。

### IDE 中的入口

首批能力以标准工程文件交付。开发者可以从终端创建，也可以在 IDE 终端执行同一命令，然后导入生成工程。安装 MadB 专用插件不是编辑和运行这些工程的前提。

后续 IDE 向导提供“新建 MadB 工程 → 选择模板与平台 → 创建并打开”。向导调用同一应用用例与参数模型，展示相同诊断，不复制生成和构建逻辑。向导是易用性增强；原生 IDE 工程可用性随对应平台主线交付。

## 2 初始化交付内容

| 内容 | 开发者得到什么 | 主要责任 |
|---|---|---|
| 应用外壳 | Android、iOS、ArkTS 等选定平台的可运行示例界面 | 展示一次真实跨语言调用的结果 |
| 共享实现 | Kotlin、Rust、C/C++ 等模板实际需要的模块 | 保持业务与平台桥接分离 |
| 边界配置 | 导出声明、必要语义、生成配置和锁 | 复用 MadB 既有边界规则 |
| 构建接线 | Gradle、Xcode、Hvigor、Cargo、CMake 之间的依赖 | 源码变化能触发正确重建 |
| IDE 入口 | 工程文件、必要源码根、运行配置和调试前提 | 能导入、索引并调用原生构建任务 |
| 工具入口 | 固定 MadB 版本的 `madbw` 与 `madbw.cmd` | IDE 与终端使用同一工具，不依赖交互式 shell 配置 |
| 质量入口 | 最小冒烟测试、CI 示例、格式与忽略规则 | 新环境能够重复验证 |
| 使用说明 | 打开位置、运行步骤、修改示例与问题诊断 | 用户无需学习 FFI 接线细节 |

只生成模板需要的模块。Kotlin 共享层调用 Rust 时，Swift 可以通过 Kotlin SDK 使用该能力，不默认再生成一套 Swift→Rust 入口。选择原生 UI 或 Compose Multiplatform 由模板配置决定；支持 KMP 不自动意味着所选目标支持共享 Compose UI。

Android 配方区分 KMP 共享模块、应用模块和按需的原生构建模块，原生库随任务和依赖自动打包。官方 Kotlin 与 CPF 配方分别构建和发布，依赖坐标映射由模板处理。SDK 消费者使用普通包依赖，不需要手工修 Maven metadata 或复制原生库。

MadB 仍是工具工程，MadB-Lab 仍是独立验证工程。初始化出来的是使用者自己的应用或 SDK，不是要求维护的第三个 MadB 产品仓库。

## 3 模板范围与节奏

| 模板族 | 交付形态 | 首批阶段 |
|---|---|---|
| `rust-c-sdk` | Rust 库、C 消费程序、CMake 工程与运行任务 | S1，验证完整初始化链路 |
| `rust-swift` | Rust SDK、Swift 消费示例和 Apple 工程入口 | S2，扩展已有 SDK 模板 |
| `kmp-app` | Kotlin 共享层、Android 与 iOS 应用 | S2 |
| `kmp-rust-app` | KMP 应用加 Rust 核心；默认 Android 与 iOS | S2；鸿蒙组合配置在 S3 独立验收 |
| `arkts-native-app` | ArkUI 应用加 profile 指定的 Rust、C 或 C++ 核心 | S3 |
| 其余原生模板 | 对应 Swift、Kotlin、Rust 与 C/C++ 主线路线的消费工程 | S4 |

模板是可以组合的模块配方，发布的是经过验证的有限配置。某条路线单独通过，不代表包含它的整个应用模板已经通过。Dart 等新增语言可以贡献自己的模板，使用相同初始化流程和验收要求。

## 4 参数与默认行为

| 参数 | 语义 |
|---|---|
| `--template` | 选择模板；未写版本时，从当前 MadB 发布目录选择固定版本并写入锁 |
| `--out` | 新工程目录；目录必须不存在，已有目录报冲突 |
| `--targets` | 目标平台列表；省略时使用模板明确列出的默认值 |
| `--profile` | 选择运行时、方向、接口能力、交付形态和构建系统均匹配的模块、UI、SDK 与工具链组合，不是任意字符串拼装 |
| `--name` / `--namespace` | 可选工程名和命名空间；默认名取输出目录，默认命名空间仅用于示例，非法值明确报错 |
| `--verify structure\|build\|run` | 默认 `build`；`structure` 只校验工程结构；`run` 还要求模板规定的模拟器或设备冒烟通过 |
| `--open <ide-id>` | 完成后打开一个指定 IDE；其他入口列在结果中，不一次弹出所有 IDE |
| `--dry-run` | 显示文件计划、工具要求、下载和验证范围；不创建工程、不下载、不执行构建 |
| `--offline` | 仅使用已存在且摘要匹配的缓存；缺项列明，不访问网络 |
| `--json` | 输出与向导共享的结构化结果，包含创建状态和分目标结果 |

默认构建覆盖本次所有选定目标；不在 Linux 或 Windows 上把未执行的 iOS 构建当作成功。模板支持当前宿主进行结构生成时，可以显式使用 `--verify structure` 先生成跨宿主源码，结果标为“已生成，待目标环境验证”。结构生成器本身也有宿主要求，不能靠降低验证级别绕过。

首次可以下载锁定的普通项目依赖和受管工具。不会自动安装系统 SDK、修改全局 JDK、接受 Xcode/SDK 协议或配置发布签名。缺少这类前提时尽早给出具体安装路径和重试命令。真机运行仍需要开发者提供自己的设备和签名条件。

## 5 IDE 可用的准确含义

| 验收项 | 需要的事实 | 不能替代它的事实 |
|---|---|---|
| 工程结构有效 | 所需文件、引用、配置和入口一致 | 文件夹存在 |
| 可以导入和索引 | 对应版本 IDE 能识别模块与生成源码，没有关键解析错误 | 命令行编译通过 |
| 可以构建 | 原生构建任务完成真实编译和链接 | 成功运行模板引擎 |
| 可以运行 | 模拟器或设备上显示正确的跨语言调用结果 | 生成了安装包 |
| 可以调试 | 声明支持的语言断点命中，源码和符号匹配 | 配置中存在 `launch.json` |

这些结果分别记录，不折叠成一个模糊的 `ready=true`。默认初始化验证到目标构建，IDE 导入/运行/调试能力由相同模板版本的 Lab 认证支撑；本机只执行过哪些检查，结果就只声称通过哪些检查。跨语言连续单步调试单独认证，不包含在普通断点支持中。

`--open` 仅表示尝试启动 IDE，不等于同步或索引完成。工程已创建后若构建失败，保留完整工程和诊断，返回非零状态；修复环境后使用项目内 `madbw build --frozen` 重试，不再对同一目录执行初始化。

## 6 发布完成条件

一个模板要被推荐给普通用户，必须通过：全新环境创建、IDE 导入、目标构建、首次运行、共享源码修改后在 IDE 重建、关闭重开、另一目录或机器复现，以及失败恢复。

SDK 模板还要从发布包创建独立消费者，验证公开接口真正可调用、native 依赖完整、平台变体解析正确；“在示例应用中能运行”不足以证明别人安装包后可用。源码/二进制交付与正向/反向调用分别声明，不能用某一方向通过代替整个语言对通过。

版本化的是 MadB、模板、模块配方、边界后端、原生构建工具和 IDE 验证组合。版本升级只改变用户明确更新的项目；不会因模板服务端变化使已有工程悄悄改写。
