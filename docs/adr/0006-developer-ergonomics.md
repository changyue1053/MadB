# ADR 0006 声明式导出与语言惯用 API

状态：本方案采用；具体宏、处理器和 UI 框架组合由对应平台探针验证。

## 背景

用户希望通过属性封装器、宏、注解和插桩降低跨端开发门槛。这些机制能减少重复代码，但在不同语言中能力不同，不能自动证明 native 所有权、线程安全或停止效果。

## 决策

1. 分开建设 SDK 作者的声明入口、消费者的惯用 API、开发者的诊断工具，复用既有契约和运行时。
2. 优先复用 UniFFI 等后端已有声明；Kotlin 优先 KSP 与生成代码，Swift 使用薄宏/库包装，ArkTS 使用经目标 SDK 验证的装饰器和生成类，Dart 使用构建期生成。
3. 普通 API 始终可用，自定义宏和 UI 包按需依赖；预生成 SDK 的普通消费者不被迫安装整套生成工具。
4. 属性访问不隐式进行阻塞调用或创建资源；页面拥有观察实例，业务 owner 拥有共享引擎。共享热流的停止策略单独声明。
5. 生成边界诊断钩子优先，字节码与编译器插桩按目标作为扩展。资源准入、所有权和线程保护不受日志开关控制。
6. 宏/处理器薄层只转换语法和元数据，生命周期与类型规则维持单一实现；错误尽量定位用户声明。

## 取舍

| 方案 | 选择理由 |
|---|---|
| 全语言统一一套神奇注解 | 不采用；语言机制不同，也会重复上游后端契约 |
| 每个宏独立实现所有生命周期逻辑 | 不采用；普通 API 与便利入口会产生语义漂移 |
| 强制全部消费者安装自定义编译器插件 | 不采用；增加依赖和 IDE 成本，普通预生成 SDK 可以避免 |
| 用诊断插桩实现必需资源保护 | 不采用；关闭诊断不应使产品失去公开安全保证 |
| 生成普通 API，再按语言增加便利入口 | 采用；便于独立消费、测试和逐语言维护 |

## 结果

开发者使用熟悉的状态、异步和作用域语法，必要的业务语义仍可见。实现成本主要是语言工具链兼容、生成来源映射、生命周期适配与独立验收，不需要为便利语法再增加一套公共运行时。
