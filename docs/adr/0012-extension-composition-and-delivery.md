# ADR-0012 跨路线扩展组合与按需交付

状态：设计采用，扩展实现与认证仍按各工作包验收。日期：2026-10-25。适用基线：0.9。关联 E01–E06、I01、L01、各路线与扩展工作包。

## 需求与范围

项目所有者要求先完整确定可扩展架构和接入要求，覆盖 Swift 及其他路线；具体扩展功能何时补充由项目所有者决定。此次仅细化架构与验收，不启动 E/X 功能、安装候选库、调整 C07 实现或改变既有任务状态和排期。

现有 ADR-0004 已确定开放身份、小型端口与版本化协议。需要补齐的部分是多个生成器、SDK 能力、UI、构建和分发工具如何形成一个确定组合，以及如何避免重叠桥接、隐藏依赖和证据误用。

## 决定

1. 采用[跨路线扩展组合与接入契约](../architecture/17-extension-composition.md)。所有路线共用能力、依赖、责任和验收规则；具体平台机制仍由适配器及 SDK 实现。
2. 扩展可以是替代实现、分阶段协作、外层增强或独立能力。每个适用的符号/语义阶段/实例作用域有唯一责任方；组合前检查依赖、目标、输出、注册器和物理库冲突。
3. 组合根解析显式选择并注入组件；规则与计划处理受检值。复用现有 TaskGraph、Wrapper、Source/Build/Candidate 事务和独立 Lab，不建设平行插件内核、执行器或认证平台。
4. 通用运行时允许手写维护；随受支持业务声明变化的必要接口和接线由生成器负责。构建工具、作者插件、消费端编译依赖、目标运行库和可选集成分别锁定、装配。
5. 对外格式继续由现有 schema 与共同向量维护。现行 v1 无法表达的跨组件必需语义，在相关实现前按受控版本演进补齐；不能塞入可忽略元数据或伪装成已有操作。此次不声称新增 wire 已实现。
6. 需求和架构可以先确定，实施时点由项目所有者选择。既有阶段、依赖和验收不自动触发开工；延期不计完成、不静默缩小主线承诺。
7. 对外可扩展性以独立作者/消费者、禁用隔离、升级兼容和无核心语言分支证明。工具/后端单独通过不能替代组合通过。
8. 初期以有限推荐配置、明确依赖及精确锁控制组合成本；公开协议支持与现有组件复用降低作者接入成本。没有实际需要时不新增物理包、强制进程或全局组合求解框架。
9. 默认使用面由普通 SDK API、业务声明和原生构建入口组成。已有工程接入/升级/禁用复用受检计划；构建优化先量化，任何执行模型变化仍须保持固定输入与事务保证。

## 对既有计划的影响

任务编号、数量、scope、phase、depends_on、状态、日期与证据不变。在已有 E/I/L/C/X 任务引用组合规范，并细化 E01–E05、I01、L01 等对应验收。具体扩展的候选库与版本在项目所有者启动该需求时按实际能力确定。

E 系列继续承担主线扩展机制，X 系列及 I07/L08 继续承担既定后续扩展；本决定不把所有可选能力移到 S6，也不要求所有扩展同时完成才允许某个独立配置交付。正式全产品验收仍满足原有全部必需条件。

## 取舍与验证

不选择“每种语言一个包揽所有责任的插件”，因为声明读取、运行时和发布的变化速度与权限不同。不选择“所有生成代码必须自动生成”，因为稳定的通用生命周期机制可以集中维护。不选择“插件可携带任意元数据解释安全语义”，因为旧核心必须准确拒绝不了解的保证。

本次设计以静态链接/目录/生成视图检查及语义复核验收；实际清单求解、组合执行和 SDK 行为仍由 E01–E06、对应路线及 Lab 证明。发生共同语义缺口时按 ADR-0004 与模型演进规范处理，不能通过扩大配置表绕过。
