# ADR 0002 Rust 核心与多语言适配器

状态：本轮设计采用，分发和工具链成本通过 P01 验证。日期：2026-10-23。

## 背景

开源工具需要可安装、可测试和可预测的执行行为；互操作生态又依赖 Kotlin、Swift、C/C++ 编译器及现有生成器。宿主 CLI 语言和目标运行时语言不必相同。

## 决策

核心模型、规则、计划和 CLI 使用 Rust。保持纯规则与副作用外壳分离。复用 UniFFI、bindgen、cbindgen、CXX、Kotlin/Native 和平台互操作机制；语言元数据帮助程序可使用最合适的生态语言。

后端通过小型端口和版本化协议连接，默认不把第三方原生插件装载到核心进程。语言运行时用对应语言实现必要组件，并复用已有绑定机制。

## 比较与代价

Python 便于脚本集成，但消费者安装和独立二进制分发需要额外解释器策略；JVM 适合 Kotlin 元数据，但增加通用 CLI 的运行环境要求。Rust 有助于单一可执行程序和明确数据模型，同时增加初期编译、跨平台打包和生态桥接成本。

这一选择不意味着 CLI 自带全部 SDK，也不意味着可以在任何系统构建任何目标。平台编译仍要求相应工具链和许可环境。

## 验证与重新评估

P01 验证安装体积、启动、跨宿主构建、帮助程序协议及故障定位。若关键生态集成无法有效隔离，先调整帮助程序边界；需要改变核心语言时以新 ADR 记录真实成本，而非沿用旧工程习惯。
