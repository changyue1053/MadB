# ADR 0004 语言扩展与核心语义边界

状态：本轮设计采用，S0/S1 的扩展探针验证实现成本。日期：2026-10-23。

## 背景

MadB 需要覆盖现有九组语言边界，并允许新增语言、运行时和互操作机制。只有按语言建目录而没有接入契约，会使差异回流到核心条件分支；只声明“插件化”，也无法证明内存、并发和分发条件已满足。

## 决策

1. 采用开放 Language/Runtime/Route 身份和受控、版本化核心语义。新增语言不自动产生与所有已有语言的路线。
2. 扩展包组合小型端口、能力清单和必要资产；同一份实现可被多个扩展引用。独立包默认通过版本化进程协议接入，组合根显式注册。
3. 清单、协议、IR、工具、SDK 与扩展各自管理版本。锁固定实际组合，未知必需语义拒绝执行。
4. 打包准备与宿主提交分离，ArtifactPackager 不拥有发布权限。声明和认证分离，Lab 负责真实消费证据。
5. 在 S0 验证框架级扩展，在 S1 以独立 Dart Native→C ABI 同步子集验证真实扩展性。该探针不改变现有主线完整交付范围。

## 取舍

新增端口的协议、身份、错误和取消测试增加初期成本，但避免依赖核心私有 API。统一 IR 只保留可明确表达的共同语义；语言差异仍有独立代码，不追求把所有 FFI 机制合并为一个运行时。

不采用庞大 LanguagePlugin 基类、不通过动态加载第三方原生库提供默认插件机制，也不把所有语言强制经 C ABI 或 JSON 中转。需要新公共语义时允许升级核心，不能用未经校验的扩展字段实现“零修改”。

## 验证与重新评估

真实探针需要只通过公开端口完成可复现 SDK 交付，并证明禁用该扩展不影响原有路线。若协议或 IR 不能表达实际要求，记录具体最小案例，优先修正规范，再调整实现；不得为了探针通过而移除失败验收项。
