# ADR-0018 有限组合的公共格式与输入身份

状态：项目所有者已确认采用，进入实现；格式、输入准入、实际执行与整包验收分别留证。日期：2026-10-26（America/New_York）。关联 E01、E02、E03，以及使用组合的 I/L/C 工作包。

## 输入与决定

项目所有者明确选择采用[具体提案修订3](../reviews/composition-decision.md)，包括 `madb.composition/1`、`madb.profile/2` 和必需功能 `core.extension-composition@1`。该提案的原设计样例及[独立审查](../reviews/composition-review.md)保持历史内容；49 项设计检查不是生产实现或整包验收。本决定不重复申请已授权的 Swift/ArkTS、CLI 归属或工作包启动。

1. 包源采用显式 file-set 与既有 `madb.source/1` 文件集摘要。manifest 原字节、包源与已安装执行镜像分别绑定；新单 port 组件身份不冒用旧 C07 聚合身份。包内路径映射到包限定的锁命名空间，不能让不同包的同名文件碰撞。SDK 资产属于包，不假造进程端口。
2. 生成资产输入只声明 producer、output_slot 与输出路径。真实字节和 generation lineage 在已有 OutputSet 与宿主检查后绑定，只向下游传递，不回写本轮 composition/profile/源锁，避免摘要循环。未产出的文件不是已完成资产。
3. 有限配方从真实受检声明、所选 SDK 与接线产生必需责任；申请者不能用自己的责任数组定义所需覆盖。比较规范来源及边界、符号、阶段和作用域，拒绝别名隐藏的重复 owner、缺项及多余项。先计算结构合格输入的身份，再完成语义与生成后检查；摘要存在不表示可执行。
4. 新 feature 只由实际需要解释组合语义的参与者协商。普通构建 helper 不机械增加此要求。旧 profile/1 的字段、摘要域和拒绝行为保持；旧执行入口不得自动接纳新格式或把它降成可忽略元数据。新格式的结构准入不授予旧路径执行资格。

完整公共字段以实施后的 schema 为权威，投影按提案约定：composition 集合排序、先拒绝重复；profile/2 复用旧字段投影，只把 composition FileRef 投影为 id 与 semantic_digest，并使用独立 `madb.profile/2` 域。未知版本、来源类别、配方和必需功能明确拒绝。

## 实施与验收边界

首个实施子范围是离线格式解码、共享正反向量、纯身份投影及输入/责任检查。复用现有协议、锁、输入字节和纯适配层；不新增控制操作、全局求解器、运行时或任务系统。协议里的端口会话与实际执行镜像仍走既有宿主准入。

真实配方、完整包闭包、生成后资产绑定、组合事务以及独立普通/增强/禁用消费者仍必须实施；结构样例或纯比较不能代替这些结果。C06/C07 历史候选及结论保持原范围，C09/C10、L04/L05 与工程链的整包退出条件、阶段、依赖不变。状态只在 catalog 维护，不由本 ADR 宣告通过或发布。
