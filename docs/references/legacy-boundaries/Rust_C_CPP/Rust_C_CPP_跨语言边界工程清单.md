# Rust ↔ C/C++ 跨语言边界工程清单

对照基线：MadB 0.9；修订日期：2026-10-24。本文为研究阅读版，保留原问题编号和历史样本；当前实施以权威规范、任务和目标证据为准。表内项目事实沿用原研究快照，本次没有重新验证旧仓库的现状，也不把风险推演当作已发生事故。

Rust↔C 的 bindgen/cbindgen 链为 S1 首链；Rust↔C++ 主线采用 CXX 并在 C08 验收。Crubit 属于 X05，现有明确 C ABI 可继续使用。

当前选型、关键更新与实施关联见[Rust ↔ C/C++ 研究整理](Rust_C_CPP_架构总结与新版_mad-boundary_设计输入.md)；精确版本只维护在[技术栈规范](../../../architecture/16-technology-stack-and-versions.md)。原文件、本机路径、旧行号及旧来源映射保存在[更新前快照](../snapshots/2026-10-24-before-refresh.zip)，原始记录不被改写。

本页共 23 项，稳定来源身份为 `Rust_C_CPP:序号`。[source-coverage.json](../../../catalog/source-coverage.json)记录修订阅读版的路径、行号、摘要及公共问题映射；原始映射可从快照中的 source-coverage.json 复核。

|---|---|---|---|---|
| **1. 两端重复维护声明** | 每条接口选择权威源，其他声明生成或编译校验；语义策略补充信息而不复制签名 | bindgen、cbindgen、CXX 静态检查、再生成检查 | 原研究：旧 mad 手写 Rust extern；MadDemo 从 mad_link.h 生成 sys.rs。 | 头、导出实现和符号均存在；生成物不手改；cbindgen 生成头不等于自动导出任意 Rust 函数 |
| **2. Rust 类型与 C ABI 不等价** | 公共 C 接口限定为有明确 ABI 的值、指针和句柄；复杂 Rust/C++ 类型通过后端支持的包装表达 | repr(C)、不透明类型、受限 DTO、CXX 桥接 | 原研究：repr(C) 不会改变内部字段自身的表示；不能据此外露任意 String、Vec 或 trait object 布局。[Rust 布局规则](https://doc.rust-lang.org/reference/type-layout.html) | 不把 Rust 默认布局当作稳定 ABI；区分 C API 的结构与 CXX 支持的专门映射；合法的特殊 Option 表示单独检查，不一概禁止或放行 |
| **3. 布局与目标配置不一致** | 将目标、宏、系统头、对齐和调用约定纳入生成输入；按承诺目标编译验证 | Clang AST、布局探针、sizeof/alignof/offsetof、编译断言 | 原研究：MadDemo 原生事件约束大小、对齐和字段偏移；该快照中的生成脚本采用特定宿主配置。 | 首链 macOS Arm64 实际双向运行；x86_64 Darwin 布局/编译另记，不当作运行结果；比较大小、对齐、偏移与调用约定 |
| **4. 非法数值直接进入 Rust 类型** | 在原始表示层接收整数，验证后构造领域 enum、bool、范围受限值和长度 | TryFrom、显式 match、未知值策略、受检算术 | 原研究：IMLink 对关闭原因和返回码逐项转换，未知值有明确处理。 | 不 transmute 未验证整数为 enum；覆盖负值、溢出、未知标志和未定义变体；错误码保留诊断信息 |
| **5. 字符串 切片与输出参数** | 明确编码、NUL、元素数/字节数、输出有效条件；先验证再构造安全引用；未初始化输出按协议处理 | CStr/CString、UTF-8 校验、MaybeUninit、容量检查、受检切片转换 | 原研究：Rust 切片即使长度为 0 也要求非空且对齐的指针；C 的 NULL + 0 应专门转换为空切片。[切片要求](https://doc.rust-lang.org/std/slice/fn.from_raw_parts.html) | 检查范围、对齐、单一分配区、初始化与借用条件；失败时不 assume_init；set_len 不超过实际初始化范围；不把 C++ string 默认当 UTF-8 |

## 二 内存与所有权

| 问题 | 处置与约束 | 工具或手段 | 历史样本／机制来源 | 验收重点 |
|---|---|---|---|---|
| **6. 分配器与释放器不匹配** | 每类返回资源声明来源、接收方、转移点和释放函数；原分配方提供对应回收能力 | Rust Drop、C++ RAII、专用 deleter、配对 free | 原研究：IMDB 返回 CString，并要求使用 imdb_string_free 归还。 | 不混用 malloc/free、new/delete、Box/Vec/CString 的回收协议；失败与取消也成对；CString::from_raw 不接收任意 C 字符串 |
| **7. 借用超过有效期** | 同步调用只借用至返回；异步保留需要复制、转移或独立 owner；指针有效期绑定实际存储 | 生命周期包装、拥有型缓冲区、操作保活 | 原研究：IMLink 声明输入在返回前复制，Rust 包装据此借用切片。 | C++ 不保存已结束的 Rust 借用；Vec 扩容、释放或移动其相关存储后不使用旧地址；Future 结束不自动结束原生借用 |
| **8. C++ 修改破坏 Rust 别名规则** | 依据真实共享关系表达引用、原始指针或内部可变性；同步必须覆盖两端访问 | 小范围 unsafe、受限访问 API、锁、必要的 UnsafeCell 封装 | 原研究：from_raw_parts 得到的共享切片在借用期间不得被外部任意修改。[借用条件](https://doc.rust-lang.org/std/slice/fn.from_raw_parts.html) | Rust 存在 &T/&[T] 时，C++ 不通过另一入口任意写入；不同时形成冲突的 &mut；UnsafeCell 不是自动同步机制 |
| **9. C++ 对象的移动与析构语义** | 非平凡对象通过间接持有操作；由正确语言执行构造、移动和析构；不能只按字节复制 | CXX UniquePtr、Pin、opaque 类型、C 包装 | 原研究：bindgen 不自动调用 C++ 特殊成员；CXX 对不透明 C++ 可变访问使用 Pin 等约束。[bindgen 限制](https://rust-lang.github.io/rust-bindgen/cpp.html)、[CXX 约束](https://cxx.rs/extern-c++.html) | 自引用对象不能因 Rust 普通移动失效；不随意 derive Copy/Clone；Pin 不替代线程安全、外部对象存活或内部容器有效期 |
| **10. 父子资源释放顺序** | 将资源依赖编码到持有关系或生命周期；区分所有权、共享引用与关闭权限 | Arc、借用生命周期、组合 owner、明确释放顺序 | 原研究：llama ContextHandle 持有 Arc<ModelHandle>，表达模型晚于上下文释放。 | 子资源使用期间父资源不释放；共享引用不产生多个关闭责任者；跨 Rust/C++ 强引用环可被打断 |
| **11. 关闭 句柄与在途调用竞争** | 自有首链按 DEC-03 登记令牌和准入；close request、await closed 与最终释放分开；第三方指针 ABI 不自动改写 | 关闭状态机、调用许可、句柄代次、停止确认、最终回收 | 原研究：IMLink 通过 Arc<Native> 保活，Engine 停止派发，最终 Drop 释放原生引擎。 | CRIT-08 验证重复 close、等待取消、旧令牌及在途调用；移除登记不提前回收已获许可的对象 |

## 三 多线程 异步与回调

| 问题 | 处置与约束 | 工具或手段 | 历史样本／机制来源 | 验收重点 |
|---|---|---|---|---|
| **12. 无依据地声明 Send/Sync** | 分别证明可跨线程转移和可并发共享；约束销毁线程、隐藏可变状态与原生全局状态 | 安全论证、受限方法、线程断言、并发测试 | 原研究：llama 对 model 声明 Send/Sync，对 context 只声明 Send；CXX 不默认给不透明 C++ 类型这些标记。[CXX](https://cxx.rs/extern-c++.html) | 不因指针可复制就生成 Send/Sync；“const 方法”不自动证明线程安全；上游实现改变后重新验证 |
| **13. 回调上下文提前释放** | 回调注册拥有明确的 context 保活责任；区分取消注册与在途回调退出；失败也必须清理 | 注册对象、引用计数、回调代次、退出确认 | 原研究：IMDB 观察接口创建泵线程，user_data 由回调使用，接口需要明确安全释放时刻。 | CRIT-03 暂停在源端已取 context 的时刻再注销；确认源端及在途访问结束前不释放；失败与同步回调均安全 |
| **14. Future 丢弃与原生工作不一致** | 分开定义停止等待、停止观察、原生取消和副作用处理；保留后台收尾责任 | 操作状态机、native cancel/stop、可等待的停止确认 | 原研究：llama 后端明确取消在词元间检查，不能据此承诺单次 decode 内即时中断。 | Future drop 不被当作原生停止证明；超时后输入仍按需存活；阻塞原生调用的取消粒度准确 |
| **15. 完成认领与结果投递竞争** | 先登记再启动；统一终态认领；等待者消失时，结果仍有明确回收者 | 单次完成通道、状态机、结果 owner、交错测试 | 原研究：场景：接收方取消后 C++ 才返回图像，投递失败不能泄漏或重复释放 | 覆盖同步完成、重复通知、注册失败与迟到结果；重复通知的资源是同一对象还是独立转移必须明确；不只依赖一次 is_cancelled 检查 |
| **16. 回调重入 锁顺序与死锁** | 默认不持业务锁调用外部代码；明确回调中允许的方法；关闭不能等待当前回调自己退出 | 锁顺序、分阶段操作、异步投递、重入测试 | 原研究：场景：Rust 持锁调 C++，C++ 同步回调 Rust，再请求同一把锁或执行关闭 | 不靠递归锁掩盖错误生命周期；回调异常有边界；析构与 join 不造成环形等待 |
| **17. 阻塞 高频事件与背压** | 原生阻塞工作使用受控线程；事件按需批量化；声明队列容量、顺序和恢复策略 | 专用线程、阻塞执行池、有界队列、批量 poll | 原研究：IMLink C++ 维护事件队列，Rust 派发线程成批处理，并校验载荷长度。 | 不在异步执行器工作线程上长时间阻塞；满队列有确定行为；有限缓冲不自动形成生产者流控；关键事件不静默丢失 |

## 四 异常 构建与交付

| 问题 | 处置与约束 | 工具或手段 | 历史样本／机制来源 | 验收重点 |
|---|---|---|---|---|
| **18. panic 与 C++ exception 越界** | 按后端声明展开与错误策略；默认在所属语言内捕获并转换；C-unwind 作为单独受验证协议 | catch_unwind、C++ try/catch、CXX Result 映射 | 原研究：IMLink 包装将部分 C++ 入口异常转换为内部错误；Rust 工作区固定 unwind 策略。 | panic=abort 不被当作可捕获；catch_unwind 不用来可靠捕获外部 C++ 异常；释放和错误查询路径也审查；普通 Result 与 panic 分开 |
| **19. 捕获失败后的状态损坏** | 区分业务错误、对象失效和进程级故障；对部分修改规定回滚、隔离或停止 | poisoned 状态、事务式更新、对象重建、失败策略 | 原研究：旧 mad 的 C ABI 防火墙区分普通 panic 与全局锁中毒；IMDB 提供独立 panic 错误码。 | 返回错误码不等于恢复一致性；AssertUnwindSafe 不是恢复证明；错误处理自身不引入未约定的二次失败 |
| **20. 编译和原生运行库不一致** | 将编译器、目标、宏、异常开关、标准库、链接模式与传递依赖纳入构建身份 | Cargo、CMake/cc、工具链锁、依赖清单、nm/readelf/otool | 原研究：llama build.rs 按目标选择构建参数，并支持经过检查的预编静态库。 | 正确链接 C++ runtime；跨端与 Release 真正消费；重复静态库不生成互相独立的全局状态；LTO/插桩能力按工具链验证 |
| **21. API ABI 与行为漂移** | 分别管理生成批次、构建产物和候选；源码/头/库配套；保持后端匹配检查并识别实际装载库 | 再生成、任务图、输入摘要、旧消费者、CRIT-06/09/10/12 | 原研究：IMLink 生成物入库并做零差异检查；这只是完整兼容验证的一部分。 | 旧输入晚到与取消不覆盖有效批次；错库明确拒绝；签名、布局、线程、取消和关闭语义分别审查 |
| **22. 零拷贝与细粒度调用成本** | 先量化真实跨界次数、复制量和资源保留成本；优先优化批量及数据形状 | 端到端基准、分配/复制计数、延迟与峰值内存预算 | 原研究：IMLink 已采用批量派发；无需为了追求零拷贝削弱其明确的输入复制协议。 | 不用空函数基准替代业务负载；借用导致长期保留的大缓冲计入成本；生命周期与性能同时验收 |
| **23. 测试只覆盖单侧或错误目标** | 建立真实双向消费者、边界值、故障注入和可控交错；记录工具与插桩覆盖 | Rust/C/C++ 集成测试、适用的 Sanitizer、模糊测试、Miri、符号化 | 原研究：IMLink 暴露专门测试钩子；Miri 对任意外部原生调用存在能力边界。[Miri](https://github.com/rust-lang/miri) | 模拟通过不等于真实 FFI 通过；覆盖原生消费者和目标设备；符号匹配产物；未执行、不支持、失败与通过分开 |

## 本路线补充

- autocxx 保留为历史生态研究，不作为新的默认选型。错误转换不证明对象恢复一致性；panic 策略与 C++ exception 在所属边界处理。
