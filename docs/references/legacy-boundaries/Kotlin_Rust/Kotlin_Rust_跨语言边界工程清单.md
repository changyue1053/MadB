# Kotlin ↔ Rust 跨语言边界工程清单

对照基线：MadB 0.9；修订日期：2026-10-24。本文为研究阅读版，保留原问题编号和历史样本；当前实施以权威规范、任务和目标证据为准。表内项目事实沿用原研究快照，本次没有重新验证旧仓库的现状，也不把风险推演当作已发生事故。

JVM/Android 使用 UniFFI Kotlin/JNA，Native 使用经修复和验证的 Gobley/UniFFI 配套；官方 Kotlin 和 CPF 的目标构建分别验证。

当前选型、关键更新与实施关联见[Kotlin ↔ Rust 研究整理](Kotlin_Rust_架构总结与新版_mad-boundary_设计输入.md)；精确版本只维护在[技术栈规范](../../../architecture/16-technology-stack-and-versions.md)。原文件、本机路径、旧行号及旧来源映射保存在[更新前快照](../snapshots/2026-10-24-before-refresh.zip)，原始记录不被改写。

本页共 26 项，稳定来源身份为 `Kotlin_Rust:序号`。[source-coverage.json](../../../catalog/source-coverage.json)记录修订阅读版的路径、行号、摘要及公共问题映射；原始映射可从快照中的 source-coverage.json 复核。

## 一 公开契约与数据

|---|---|---|---|---|
| **1. 后端与导出能力** | JVM 使用 UniFFI Kotlin/JNA，Native 使用经 P03 修复和验证的 Gobley 配套；能力按版本、目标、方向和类型独立登记 | UniFFI/Gobley 元数据、模板补丁、Kotlin/JVM 与 Native 实际消费探针 | 原研究：MadDemo fork 明确拒绝 async / Object，避免输出未经验证的 ABI。 | JVM 支持不能自动算 Native 支持；上游能力不能自动算 fork 能力 |
| **2. 模型权威源与数据语义** | Rust SDK 契约可以定义在 Rust；生成 Kotlin 类型，领域隔离需要时再做 Port 映射；区分值数据、资源代理与句柄 | Record / Enum 生成、受限 Adapter、类型契约 | 原研究：MadDemo 的 `uniffi.toml` 生成只读字段记录，领域端通过 `UniffiImLinkPort` 映射；`val` 不自动保证所有嵌套内容不可变。 | 是否复制、是否共享、修改是否回写有明确说明；不重复维护等价业务模型 |
| **3. 数值 可空值与稳定 ID** | 区分 `u64 / ULong / Long`、范围、单位、空值和业务身份；跨模型枚举按语义映射 | 受检转换、强类型 ID、穷尽映射、边界值测试 | 原研究：MadDemo 集中使用 `WireRange`，入参越界拒发，入站越界按协议处理；上限字段的饱和转换另有明确规则。 | 不截断、不误用默认值；不把句柄当业务 ID；不靠两套枚举的 ordinal 对齐 |
| **4. ABI 表示与输入校验** | 使用选定后端的 ABI；手写 C ABI 时明确布局、长度、编码及释放函数；业务入口另验范围和大小 | 生成绑定、cbindgen、cinterop、布局探针、参数校验 | 原研究：UniFFI 对复杂数据采用内部缓冲区表示，并非直接暴露任意 Rust 类型布局。[转换机制](https://mozilla.github.io/uniffi-rs/latest/internals/lifting_and_lowering.html) | 目标宽度与布局正确；非法输入得到稳定错误；不能将 Rust `String / Vec` 的内部布局当公共 C ABI |
| **5. 名称与生成 API 冲突** | 检查关键字、目标语言基类成员、重载与跨模块名称；允许显式重命名 | 生成前诊断、实际 Kotlin 编译、API 基线 | 原研究：MadDemo fork 拒绝与 Kotlin Throwable 的 `message / cause` 属性冲突的错误字段。 | Kotlin 接口可直接编译使用；改名可追踪，不能静默丢字段 |

## 二 调用与异步协议

| 问题 | 处置与约束 | 工具或手段 | 历史样本／机制来源 | 验收重点 |
|---|---|---|---|---|
| **6. 业务失败与 panic** | 业务失败使用 Result / 稳定错误；panic 在边界封闭，并定义故障后资源是否仍可用 | UniFFI Error、错误目录、panic 边界、故障注入 | 原研究：MadDemo 的错误码在 Rust 统一定义，导出门通过 `guarded` 捕获展开式 panic。 | 不把内部故障当普通业务拒绝；不能因捕获 panic 就认定状态可安全继续 |
| **7. Kotlin 反向回调失败** | 明确允许的回调错误、未知异常和交付失败；将恢复动作交给所属领域 | trait / callback 绑定、错误适配、交付状态、回调故障测试 | 原研究：MadDemo 存储监听器失败按接不住处理；网络监听器失败进入链路交付失败路径。 | 异常不静默吞掉，不把丢失的批次当成功；恢复范围与错误分类一致 |
| **8. 执行位置与阻塞** | 分别声明调用执行器、回调执行器和阻塞性；存储、推理等阻塞调用使用适当执行位置 | Dispatcher、主线程守卫、执行器适配、耗时测试 | 原研究：MadDemo 的 `KernelRuntime.call` 集中执行主线程检查；检查本身不负责切线程。 | 重 I/O 和长计算不占 UI 线程；同步函数、非阻塞受理、async 分开建模 |
| **9. async 运行时与任务归属** | 确认绑定支持；明确 Future 由谁驱动、是否依赖 Tokio 等运行时、任务随谁结束 | 选定版本的异步桥、运行时 Adapter、Scope 策略 | 原研究：上游 UniFFI 能桥接 async；MadDemo fork 将其排除在验证范围外。[官方机制](https://mozilla.github.io/uniffi-rs/latest/internals/async-overview.html)、 | async 不被当作自动后台执行；运行时要求满足；任务无隐式永久存活 |
| **10. 取消 超时与副作用** | 区分停止等待、请求停止工作和撤销结果；结果未知时采用领域定义的查询、幂等或补偿 | 取消接线、操作 ID、协作式取消、超时测试 | 原研究：MadDemo 网络超时只放下等待，远端在途名额仍保留；推理通过回调读取取消信号。 | 取消效果准确；不提前归还仍被占用的容量；已提交事务不被误认为撤销 |
| **11. 重入 完成竞态与结果交接** | 先登记再触发；计算错误与终态通知失败分开；成功认领后不得再次错误完成，投递失败的资源单独清理 | 修复后的 foreign future 模板、单次完成状态机、CRIT-02/03 屏障 | 原研究：mad 关户最后一批事件在关闭调用线程同步交付；MadDemo 在发送前登记等待者。 | 覆盖成功通知抛错、重复完成、取消和迟到资源；模板修复可重生成，不能只升级 runtime |
| **12. 订阅 背压与事件恢复** | 明确订阅数量、退订能力、容量、顺序、溢出和快照水位；状态合并与可靠事件分开 | Channel、Flow Adapter、序号与水位、故障注入 | 原研究：MadDemo 存储常驻单订阅，以 `commit_seq` 与快照恢复；网络响应不能合并，队列满按链路失效处理。 | Flow 包装不凭空创造退订能力；慢消费者行为明确；恢复后不跳号、不重复应用 |

## 三 所有权 内存与多线程

| 问题 | 处置与约束 | 工具或手段 | 历史样本／机制来源 | 验收重点 |
|---|---|---|---|---|
| **13. 资源 owner 与句柄有效期** | 明确唯一关闭责任、允许的共享引用、句柄作用域和准入规则；复用句柄槽位时防止旧身份误命中 | 资源包装、注册表、状态机、保活引用 | 原研究：MadDemo 存储表区分 Opening / Ready / Closing，关闭时撤句柄，在途引用与底层关闭另行协调。 | 释放引用与关闭业务资源分开；不会因 Arc 尚在就允许对已关资源继续操作 |
| **14. 缓冲区寿命与释放配对** | 声明复制、借用或所有权转移；分配与释放使用配套模块；借用指针不逃逸其有效期 | UniFFI 缓冲转换、cinterop 作用域、受控批量复制、内存测试 | 原研究：UniFFI 的 RustBuffer 与手写 C ABI 有不同管理协议，应由对应后端承接。[表示机制](https://mozilla.github.io/uniffi-rs/latest/internals/lifting_and_lowering.html)、[cinterop](https://kotlinlang.org/docs/native-c-interop.html) | 错误、取消、转换失败路径也释放；零拷贝有独立的寿命与并发证明 |
| **15. GC 与 Rust 引用环** | 登记和撤销回调配对，解除 Kotlin 对象与 Rust 资源互持；确定性资源显式关闭 | 绑定生命周期 API、弱引用、解除注册、长期运行观测 | 原研究：UniFFI foreign trait 可能形成跨语言循环引用，绑定工具不会自动消除所有环。[官方说明](https://mozilla.github.io/uniffi-rs/latest/foreign_traits.html) | Kotlin GC 与 Rust Arc / Drop 的存在不被当作无泄漏保证；正常析构不报成泄漏 |
| **16. 关闭的取消与超时** | 关闭由正确 owner 驱动，区分已完成、仍在关闭与放弃；不能因等待超时提前释放在途内存 | 专用关闭作用域、必要的不可取消段、排水、关闭报告 | 原研究：MadDemo 关库使用 `NonCancellable + lifecycle`，避免派发前取消导致关库被跳过；阻塞关闭仍可能超过等待预算。 | 调用者取消不会让必需清理永久丢失；超时状态与实际资源状态一致 |
| **17. 两侧同步与回调重入** | Rust 和 Kotlin 遵守同一访问协议；不持业务锁等待回调；区分线程安全与操作原子性 | Rust Mutex / Arc、Kotlin 原子或 Mutex、串行域、适用范围内的竞态工具 | 原研究：Rust 的 Send + Sync 无法替外部 Kotlin 实现证明线程安全；MadDemo 回调入队，协调集中到串行域。[官方约束](https://mozilla.github.io/uniffi-rs/latest/types/callback_interfaces.html)、 | 并发关闭、重入、共享可变字段均受保护；无锁内跨语言调用形成的互等 |

## 本路线补充

- 调用 async 不保证阻塞工作自动离开调用线程；Rust Future 的驱动方、运行时和关闭策略需要明确。
