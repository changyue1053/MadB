# MadB 关键边界场景与独立预期

这些是用于实施的测试规范，不是已经运行的结果。每个场景先选择确定 profile、目标、方向、制品摘要和预算；不存在对应能力时验证明确拒绝，不能用一个通用成功路径覆盖所有后端。公共问题仍为 48 个、基础组仍为 96 个，本页把部分组展开为可执行的时序要求。

## CRIT-01 排队后停止观察

前提：有一个可暂停的目标执行器、一项已注册观察；native 源和投递适配器具有声明的注销/保活协议。

1. native 产生载荷，适配器取得投递票据并排入目标队列；暂停执行器，允许 native 回调返回。
2. 请求停止，禁止新投递准入，并按契约处理源端注销。
3. 恢复执行器；旧队列项在执行器中检查订阅代次，并与停止共享同一准入同步协议。
4. 已停止的条目只回收载荷；已进入用户回调的条目必须退出后才能确认停止。
5. 停止成功后继续触发事件，消费者调用计数保持不变，队列与 native context 按各自责任最终清理。

独立预期：停止确认后用户调用增量为 0；转移载荷的接管次数加释放次数等于创建次数。对无法撤销的队列项，可以先确认“不会再调用消费者”，但只有票据最终归还才确认资源释放完成。反例删除执行器侧门控时，测试必须检测到迟到的页面调用。

重入另建子用例：用户回调内 requestStop 后正常返回，外部 owner 才 awaitStopped；不得在该回调内同步等待自身退出。

## CRIT-02 完成后取消接收

前提：返回需要明确释放的资源，能暂停 continuation/目标执行器；测试使用该后端真实完成协议。

1. 原生创建一个资源，完成通知进入桥，终态被认领。
2. 在目标代码尚未取得结果时取消等待，随后恢复执行器。
3. 未交付资源由受管取消清理路径接管；如果接收已胜出，清理责任属于消费者。
4. 另做“完成通知后注入异常”子用例，断言不能再发失败终态。

独立预期：每次操作恰好一个终态责任方；每个转移资源恰好一个接收/清理责任方；native 工作计数在真实工作退出前不归零。不能只看 Promise/Future 最终值，也不能复用生产状态机计算预期。Gobley 旧模板复现放在隔离测试构建，候选使用受管修复模板。

## CRIT-03 源端已取走 context

前提：fixture 可在原生线程取得 callback/context 之后、调用桥入口之前暂停。

1. 暂停该原生线程，然后另一线程请求退订和释放。
2. 有注销屏障的后端必须等待此调用归还源端持有；采用登记租约的后端必须维持 context 有效。
3. 恢复源端，完成允许的回调或被门控的清理，再确认可释放。
4. 去掉注销屏障/租约的负例必须由契约检查拒绝；若故障注入验证动态检测，在独立进程执行。

独立预期：入口内第一次读取 context 时它仍存活；最终释放一次。仅在桥函数第一行加 in-flight 计数不满足此条件。后端不能证明注销或保活时，强停止及及时回收配置不得进入推荐 SDK。

## CRIT-04 两入口唯一内核

前提：例如 Swift→Rust 与 Swift→Kotlin→Rust 同处一个应用，并且装配契约要求共享一个内核。

1. 创建唯一业务 owner，将受检适配入口连接到同一实例；两个绑定的句柄仍分别管理，不直接互传。
2. 入口 A 修改测试状态，入口 B 读到同一 revision；核对测试专用实例身份、创建数及链接清单。
3. 关闭 A 的观察后，B 继续工作；最终 owner 关闭后两个入口均拒绝新调用。

独立预期：实例创建数为 1、最终释放数为 1、两入口读取一致；错误装配成两个内核时该用例失败。测试 ID 不进入生产业务协议。相同 checksum 结果或链接成功不能代替此预期。

## CRIT-05 只读查询与检查

准备三组输入：新鲜快照、缺快照、源码改动导致过期快照。记录进程调用和工作区文件摘要。

- inspect/check 对新鲜快照可执行；缺失/过期时说明 MetadataRequired，附 metadata 前置任务，不启动编译器。
- plan 可返回准备图，不执行图；显式 metadata 构建完成后才生成完整图。
- generate --check 在隔离临时目录复算；漂移时返回非零，源码、锁、有效生成目录的摘要不变；临时目录按策略清理。
- 在错误恢复、离线缺依赖及并发查询条件下重复上述检查。

独立预期来自文件摘要、进程记录和返回类别，不仅是 CLI 输出“只读”。

## CRIT-06 取消与候选提交

分别构造两个交错：取消记录先于结果接受；结果接受并完成提交判定先于取消。不能用墙钟时间猜测顺序，使用宿主提交屏障。

前者即使收到 ok 也不得提交；后者返回已完成，不能假装撤回已提交内容。重复结果、迟到写入、错摘要或缺文件进入明确错误；清理未确认不能写 cancelled。对远程扩展再注入截断下载、错来源、同键异内容与上传失败，缓存命中不改变测试/认证状态。

每次重试使用新请求身份和受管 staging。协议状态机、当前候选索引及实际文件摘要作为独立观察。未实现远程后端时，只执行本地 E02/C10 分支，不虚报 X09 通过。

## CRIT-07 身份、策略与摘要

准备两个同名重载、一个显式公开 ID 和一个策略族，输入包含字段顺序、数值边界及来源位置。

1. 正常读取并绑定精确选择器；重复读取、改变 map 键顺序及工作目录，核对公开身份、语义摘要和生成文本一致。
2. 移动源码行时来源位置更新、形状摘要不变；改变参数顺序、取消效果或工具身份时，对应结构/策略/任务摘要改变。
3. 分别注入重复 public_id、名称简写多命中、零命中、两个显式释放器及两个默认族定义同属性；均在生成前拒绝并定位来源。
4. 对 64 位整数和精确浮点常量比较预先固定的规范编码向量，不能由被测序列化器生成期望。

独立预期：策略只作用于指定声明；错误时有效输出不变；默认与显式来源可追溯。默认值被显式值合法替代的正例必须与双显式来源冲突负例分开。

## CRIT-08 关闭与移除登记

前提：使用 DEC-03 的自有首链登记令牌；已有裸指针库使用对应包装配置，不在释放后解引用悬空指针。

1. 创建资源并启动可暂停操作；并发重复 requestClose，新操作返回 Closing，原有许可仍保活资源。
2. 等待超时后尝试 releaseHandle，返回 Busy；资源仍有合法收尾 owner。
3. 恢复工作并完成所承诺清理，awaitClosed 成功；有效登记上的普通调用返回 Closed。
4. releaseHandle 成功移除登记；再次使用该令牌返回 InvalidHandle，新资源获得不同令牌。
5. 回调内请求关闭可返回，回调内等待关闭返回 WouldDeadlock；外部 owner 可在回调退出后等待成功。

独立预期由 fixture 计数和 barrier 证明：原生对象最终释放一次，登记不在关闭前移除；输出参数在失败路径保持安全值。对任意无效地址崩溃不能算“重复释放检查通过”。

## CRIT-09 生成事务与构建并发

1. 构建开始时固定批次 G0；暂停旧输入 A 的生成。修改输入启动 B，完整生成并提交 G1。
2. 允许 A 完成。输入/索引复核必须阻止它替换 G1；同身份重复任务可复用既有结果。
3. G0 的消费者继续只读 G0，新的消费者固定 G1；任何一次链接都不能混用两代头/包装/库。
4. 分别在文件写入中、文件完整但索引未更新、索引更新后终止生成进程，再启动恢复；有效索引只能指向完整一代，仍被读取的目录不能被 GC。
5. 另构造同输出域的 IDE/CLI 并发和 Gradle→MadB→原调用任务的循环，前者可等待/冲突返回，后者在启动递归子任务前拒绝。

独立预期使用外部文件摘要、索引代次、进程记录及固定消费输入；不能只断言程序打印“原子”。源码提交后的链接失败不得把新源码搭配旧二进制发布为 ready SDK。

## CRIT-10 输入追踪与缓存

以已成功的冷构建为基线，分别只改间接头文件、宏/cfg、白名单环境、工具补丁、生成输入目录中的文件集合与可选头文件的存在条件。

每次必须触发受影响任务；无关输入变更按声明范围保留可复用结果。冷构建与增量结果由独立消费比较，不能只比较缓存键。再注入损坏缓存、缺失依赖清单及生成期间源码改动；分别重建/保守失效/拒绝提交或改用稳定输入快照。修复后正常增量路径仍通过。

CRIT-09 证明提交顺序，CRIT-10 证明输入收集完整；一个通过不能代替另一个。无法完整追踪的任务禁用缓存，不能将未命中观察误标成稳定增量能力。

## CRIT-11 队列满载与环境退出

前提：固定执行器 owner、线程约束、项数/字节预算与可暂停消费者。分别构造 state 和 event 实例，并保留不满载的成功对照。

1. 以小载荷填满项数上限，再以大载荷触发字节上限；检查配置的合并或 ResourceExhausted 行为，所有拒收/替换载荷均由唯一合法方清理。
2. 在业务队列满时请求停止和关闭，验证控制/收尾不依赖已停止消费的同一队列，也不产生无界临时队列。
3. 注入同步反调等待环和回调内关闭等待，验证准确拒绝；正常重入查询及非阻塞停止仍成功。
4. 在 env 有效时开始退出，记录生产停止、用户回调门控、环境引用释放和执行器销毁顺序；纯 native 迟到结果按声明 owner 清理。

独立预期：停止后无新消费者入口；清理发生在合法线程/环境；内存与票据回到基线。对无法提供退出前清理的后端，准入检查拒绝强保证配置；不得在 env 失效后尝试其 API 并把异常吞掉。

## CRIT-12 错库与发布身份

1. 干净消费者使用固定候选的头/包装和库，执行实际公开调用；记录编译、链接及初始化检查各自范围。
2. 分别替换旧库、错误目标、不同 ABI/profile、缺 bootstrap 或错上游 checksum 的库，匹配预期检查阶段。不能靠业务函数偶然崩溃判通过。
3. 在受管安装测试中注入错文件摘要、错误发布仓库/工作流身份、缺少规定来源证据；验证不执行该下载工具，不提交候选。
4. 升级候选验证失败后，原锁与有效批次仍可用；已验证候选重新打包/编译产生新字节时，原证据不得自动沿用。

自有 bootstrap、上游校验和不可修改外部库分别实例化。没有运行时查询能力的配置按其声明的文件/链接检查验收，不能冒称运行时自证。真实公开渠道下载在发布阶段执行；S1 的隔离安装 fixture 不等同公开发布成功。

## 报告与清理

每个实例保留 barrier 事件序列、资源/票据计数、结果分类、制品与工具身份以及清理结果。资源必须回到测试初始基线；无法安全清理时保留隔离状态并报告 error。watchdog 默认用于识别挂起和收集证据，杀死测试进程不证明 SDK 停止协议成功。
