# MadB 新增语言接入与验收

新增语言以一条明确的路线和一个固定配置开始，再按功能和目标扩展。接入完成需要可读声明、可复现构建、惯用 SDK、真实消费验证及可追溯证据。生成器能输出文件，只完成其中一个环节。

本规范同时用于新增语言、运行时、后端和组合路线。公共行为问题继续引用[问题目录](04-problem-catalog.md)，本页的 EXT 编号是扩展接入门禁，不取代现有问题与案例编号。

## 1 接入工作包

| 次序 | 必需输入或交付 | 责任角色 | 退出条件 |
|---|---|---|---|
| 1 范围 | provider、consumer、方向、目标、桥接机制、首批功能及明确排除项 | 扩展维护者 | 一份确定的路线说明 |
| 2 可行性 | 上游机制、工具链、分发前提、最小手工互调探针 | 平台维护者 | 数据、错误和必要资源路径可复现 |
| 3 契约 | 结构权威源、映射、所有权、线程、取消和能力缺口 | 架构负责人 | 现有 IR 可表达，或先完成模型演进 |
| 4 接入 | 清单、端口实现、模板和必要 SDK 组件 | 扩展维护者 | 无核心语言分支，协议与结构测试通过 |
| 5 行为 | 实际消费程序、正反例、语言特例和故障复现 | 验证维护者 | 必需行为测试有真实结果 |
| 6 交付 | 固定包、来源与工具锁、安装说明、许可清单 | 发布维护者 | 干净环境消费与发布门禁通过 |

范围、实现和验证状态沿用现有三维模型，不合并成一个“支持”布尔值。设备或 SDK 不可得时，可以继续提交实验实现，但相关认证仍缺失。

## 2 必需验收组

| 门禁 | 检查内容与典型负例 | 关联公共问题 | 主要执行位置 |
|---|---|---|---|
| EXT-01 清单与注册 | 重复 ID、错误端口引用、依赖环、目标错误组合 | CAP-001、CAP-004 | MadB |
| EXT-02 协商与身份 | 无共同版本、未知必需功能、清单摘要和入口不符 | CAP-002、CAP-004 | MadB |
| EXT-03 协议健壮性 | 畸形/超大帧、重复结果、崩溃、取消竞态和输出越界 | GEN-001、OBS-001 | MadB |
| EXT-04 结构与映射 | 数值边界、空值、编码、未知变体、不支持类型准确阻断 | TYPE-001 至 TYPE-008 | MadB 与 Lab |
| EXT-05 生命周期 | 错释放器、重复关闭、借用逃逸、迟到结果和引用环 | LIFE-001 至 LIFE-008 | Lab |
| EXT-06 异步与线程 | 同步回调、重入、取消确认、环境退出、队列与错误执行器 | ASYNC-001 至 ASYNC-005、THR-001 至 THR-004 | Lab |
| EXT-07 错误边界 | panic/异常、业务失败、工具失败不混淆，失败后状态明确 | ERR-001 至 ERR-003 | MadB 与 Lab |
| EXT-08 生成质量 | 确定性、来源、手写文件保留、失败不覆盖有效输出 | GEN-001 | MadB |
| EXT-09 实际使用 | 真实消费语言、公开 SDK、直接调用与已声明反向路径 | VERIFY-001、UI-001 至 UI-003 | Lab |
| EXT-10 交付与兼容 | 精确锁、全新环境、Release、目标加载、包与证据一致 | BUILD-001 至 BUILD-005、COMP-001、COMP-002、DIST-001 | Lab 与发布门禁 |
| EXT-11 性能 | 跨界频率、复制和内存峰值；固定环境基线与预算 | PERF-001 | Lab |
| EXT-12 架构扩展性 | 核心依赖不变、未知语言身份可登记、禁用扩展不损坏其他路线 | CAP-001、VERIFY-002 | MadB |

不支持异步的首版路线，EXT-06 仍要验证异步请求被准确拒绝；不会运行不存在的异步成功路径。无 UI 的路线需注明 UI 行为不适用，不能把环境退出或资源释放一并排除。每个排除项都必须有按 profile 判定的理由。

EXT-01 至 EXT-03 的 JSON 示例可做设计期结构检查；完整门禁必须包含进程、文件、真实编译器和运行时测试，不能用 schema 校验代替。

## 3 独立预期与真实消费者

公共预期来自语义规范，由 Lab 独立维护。例如最终释放恰好一次、取消确认后不再交付、整数无损或显式报范围错误。不能调用生成器内部映射函数计算预期，再用同一个映射证明结果正确。

共享场景可以参数化，但每种运行时必须有实际消费者。单语言替身、桌面替代平台和插桩构建只能提供相应级别的证据；正式候选还要使用未插桩 Release 包验证装载及关键行为。

语言特有的问题保留专门案例。新增 Dart 时应独立检查其执行环境约束、回调可达时机与资源清理方式，具体条件由选定后端和目标探针确定，不直接继承 Kotlin、Swift 或 ArkTS 的线程结论。

## 4 扩展性探针

在 S0 使用测试专用虚构语言身份和两个最小适配器，验证注册、版本选择、未知功能阻断和依赖方向。它只证明扩展框架可接线，不证明任何真实语言可用。

在 S1 增加一个独立打包的非主线消费扩展作为真实探针。当前选择 Dart Native→C ABI 同步子集，限定一个经过探针确认的目标，包含类型传递、错误、显式资源关闭和干净环境消费。该探针验证既有核心能被第三方形式复用，不把 Dart 的全部平台和异步能力加入当前十六条主线承诺。

真实探针必须通过：核心 model/rules/plan 无语言分支；只依赖公开端口；禁用该扩展后原路线照常运行；扩展旧版本与新版本的锁互不污染。若发现公共语义缺口，按 ADR 演进核心，完成受影响回归后重新判断探针结果。

上述 S1 探针是 E04 和 E05 的基础子交付。E05 的整包符合性还须验证本版本已承诺的语言增强与允许组合，在 S5 收口；各配置就绪即可提前执行适用 EXT，不因整包阶段后移而推迟必要检查。具体依赖及联合切片输入见[实施计划](../delivery/01-implementation-plan.md)。

### 独立扩展作者的最小旅程

E04/E06 的作者从公开模板开始，只实现该扩展缺失的端口或映射，复用已公开的 Reader、Toolchain、Packager 和协议支持。用独立包完成声明、精确锁、生成、候选消费及禁用，不复制内部驱动、不修改核心私有代码，也不为五个端口各建一个新实现。框架提供的通用部分与作者实际编写部分分别记录。

该旅程证明可操作的接入成本；模拟握手、一个空插件或核心没有新增语言分支均不能单独通过。公共帮助库减少重复工作，宿主与 Lab 的独立检查仍然执行。

## 5 UniFFI ArkTS 实验后端准入

X07/P13 在既有 ArkTS/Rust 语言组内验证新后端，首轮只是实验候选，不自动增加主线路线 ID。S0 可以提前探针，正式扩展验收留在 S6；实验失败不改变 S5 主线范围。

- 固定 beta 生成器、其匹配的 UniFFI 版本、runtime、补丁和目标 SDK。不能把它与 Gobley 或另一条 UniFFI 配置的生成物混用。
- 逐项声明支持的类型、对象、async、回调、取消和环境退出；不从 README 的功能概述推导所有形状都可用。
- 实际 ArkTS/HAP 调用与设备执行满足适用 EXT 门禁。脚本未配置设备而只完成 native 构建时，只能记录相应编译证据。
- 与 napi-ohos 主线分开维护能力、维护责任和证据。只有独立验证、许可和公开消费都具备后，才决定是否推荐。

具体候选与来源见[技术栈选型](../architecture/16-technology-stack-and-versions.md)，不在此另设平行版本表。

## 6 证据与发布

认证记录至少关联扩展包及清单摘要、组件绑定、protocol/IR、核心规则版本、工具与 SDK 版本、目标、契约摘要、候选包摘要、Lab revision、案例实例、适用性与实际结果。

认证不得由扩展自报的 testsPassed=true 触发。Verifier 返回观察，宿主和发布门禁核对独立案例结果及候选身份。第三方无设备证据时维持实验状态，不能用作者声明替代缺失结果。

扩展、映射规则、必要 SDK 组件或工具链变化时，相关证据重新计算；无法可靠推导影响时按保守范围失效。旧组合可保留已知结果，但新的候选不得继承旧组合的通过状态。

## 7 新语言 PR 的完成清单

- [ ] 清单及相对路径合法，所有依赖可锁定，公开组件引用存在。
- [ ] 首批范围清晰；未支持能力有明确诊断，未被自动降级。
- [ ] 类型、错误、所有权、线程和取消的适用语义已定义。
- [ ] 端口协议、生成质量和架构依赖测试通过。
- [ ] 公共问题适用性与语言特例完整，真实消费者具有独立预期。
- [ ] 精确候选通过新环境安装、构建和消费，包、文档与证据一致。
- [ ] 贡献说明能让另一位开发者独立复现，许可与维护责任明确。

条目完成状态必须链接实际结果，不能只勾选。本文所有门禁在代码实现前均为待执行的验收要求。

## 8 多组件组合与独立业务声明

按[跨路线扩展组合](../architecture/17-extension-composition.md)执行以下适用验证，复用已有 EXT 编号，不创建新的测试平台：

- EXT-01/02/12：注册和版本解析不依赖安装顺序；禁用扩展后基础路线可消费，锁和运行依赖不被其他配置污染。
- EXT-03/08：各组件独立校验会话、输入和输出；重叠文件 owner、无依赖的输出引用、取消后提交或部分成功拼装必须拒绝。
- EXT-04/05/06：同一符号/语义阶段/实例作用域存在唯一责任方；合法的多订阅与重复自动订阅分开验证，拒绝增强层虚构的取消、线程或资源保证。
- EXT-08/09：使用独立于首个固定 fixture 的业务模块，在承诺声明子集内增加接口或模型，正常重生成后由公开 SDK 消费；不支持声明准确拒绝，不要求修改工具私有代码。
- EXT-09/10：验证基础配置、承诺的增强项与允许组合；构建工具不被误交付为运行依赖，必要运行库不遗漏；源码共同构建和二进制分发分别留证。
- EXT-10/12：升级失败保留旧锁和完整批次；禁用为下一次构建选择，不能把动态卸载、终止进程或 GC 当作资源关闭证明。

无环境或未实现的组合保留缺失。结构样例、两个组件单独通过、两两兼容或核心依赖图不变，均不足以证明完整组合。

ArkTS 的十二项扩展按 [ADR-0017](../adr/0017-arkts-extension-delivery.md)登记选择与归属，验收复用本节和 [DX/INIT](07-developer-ergonomics.md)中的实际消费实例。UI、异步/响应式及资源便利层对照普通 API，不能新增隐藏订阅、跨 env 引用或未经声明的停止保证。EXT-09/10 检查源码 HAR、字节码 HAR、HSP、私仓/离线等已选择形态及依赖闭包；EXT-01/02/12 检查禁用增强后基础入口仍可消费。消费者可选不代表产品已承诺的交付可以省略。

KNOI、ANI、UniFFI ArkTS 等替代后端继续按各自 S6 工作包准入；其可行性探针不升级主线认证。专用向导复用初始化用例，诊断扩展保留未启用对照；C11 所需产品前置由 ADR 和任务目录统一规定，不从某个扩展实例反向创建主线完成依赖。
