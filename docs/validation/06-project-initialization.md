# MadB 工程初始化与 IDE 验收

本套件验证 [REQ-13](../product/01-positioning-and-requirements.md) 及[初始化体验](../product/04-project-initialization.md)：使用者从发布工具创建新工程，在声明支持的 IDE 中开发和运行。模板文本快照测试保留在 MadB；真实工程消费与结果断言由 MadB-Lab 独立维护。

## 1 认证单元

最小认证单元是 MadB 版本、模板包摘要、template_profile 及引用的 boundary_profiles、目标/ABI、宿主 OS、工具链与 IDE/扩展版本、验证场景的组合。语言路线认证是前提，不替代模板整体认证。

工程结构、IDE 导入索引、命令行构建、运行、调试分别产生证据。IDE 启动成功不是导入成功；无界面构建不是 IDE 索引测试；模拟器执行不是实机验证。所宣称的每个目标必须有实际必需结果，失败、跳过、基础设施错误和不适用分别记录。

## 2 必需验收组

| 编号 | 场景 | 通过要求 |
|---|---|---|
| INIT-01 | 干净环境一键创建 | 从候选工具和模板开始，显式前提之外不手写接线；全部必需目标达到请求级别 |
| INIT-02 | 原生 IDE 导入与索引 | 按给定入口打开，模块与生成源码被识别，最小业务 API 能导航/补全，无关键解析错误 |
| INIT-03 | IDE Run 首次调用 | 示例界面显示真实跨语言计算结果；不能用写死文案或进程存活替代 |
| INIT-04 | 修改共享代码后再次 Run | Lab 改变提供方返回值，并增加一个导出函数；在 IDE 构建后消费端能调用新函数并看到新结果 |
| INIT-05 | 独立调试能力 | 声明的宿主/native 语言断点分别命中，符号和源码正确；连续跨语言单步有额外场景才可宣称 |
| INIT-06 | 环境缺失与不可构建目标 | 缺 SDK、错误 JDK、不支持的 IDE/宿主或构建方向准确失败；使用技术栈文档的实际条件，不把 CLI 可运行当作目标可构建 |
| INIT-07 | 提交与失败恢复 | 暂存错误不留下正式工程；最终路径构建失败保留完整工程；修复后可用 Wrapper 重试 |
| INIT-08 | 文件所有权与冲突 | 既有目录、并发初始化、用户改业务/构建脚本均不会被覆盖；受管绑定可再生 |
| INIT-09 | 工具一致性与离线 | CLI 与 GUI PATH 不同仍使用锁定 Wrapper；断网有缓存成功、缺包准确失败；校验不符拒绝执行 |
| INIT-10 | 路径可移植性 | 换目录、另一台机器、空格/中文路径按声明能力通过；不支持者预检解释，不在深层构建时隐式崩溃 |
| INIT-11 | 构建依赖与并发 | IDE 直接构建、CLI 构建均正确；拒绝循环任务；并发不死锁，不读到旧绑定或混目标制品 |
| INIT-12 | 组合配置与扩展模板 | 不兼容编译器/目标/包装方式被拒绝；官方/CPF 独立 GAV 与根 metadata；新增模板通过公开资产接口接入，无核心语言分支 |

这些 INIT 编号属于工程体验验收组，不重新编号原有 48 个边界问题或 96 个边界案例组。遇到相同底层问题时引用既有目录；模板新增独立缺陷再按问题目录流程登记。

## 3 平台配方的必需实例

| 配方 | 关联 INIT | 必须覆盖的实例 |
|---|---|---|
| AGP 9 Android/KMP | 02、03、04、11、12 | shared 使用新 KMP 插件，app 独立；预构建 `.so` 以受管 `jniLibs` 接入，需 `externalNativeBuild`/多 variant 时使用独立 Android library；host/device tests 显式启用并真实执行 |
| Android SDK 发布消费 | 01、03、04、09、11 | 新消费者仅声明 AAR/SDK 依赖就带齐 native 库与规则；源码变更会重建，不依赖 app 临时补库或旧缓存 |
| 官方 Kotlin/CPF 双根 | 01、04、09、12 | 独立 Wrapper、输出、缓存和 Maven GAV；正确变体可消费，错坐标不悄悄选中另一条线；正式 SDK 和 Konan sysroot 分开 |
| SKIE 二进制 SDK | 01、02、03、09 | 发布模板显式配置可分发 framework，异机真实调用 API；custom cinterop 不可用占位不能伪装成初始化成功 |
| Swift C++ | 02、03、04、06、12 | direct-source 与 C/ObjC++ SDK 包装分开；构建系统、interop 依赖传播和方向符合声明；SwiftPM 的反向直接消费请求被阻断或显式改选受支持配方 |

IDE 版本、宿主 OS 和候选工具的具体值引用[技术栈选型](../architecture/16-technology-stack-and-versions.md)。每个实例仍为待实现/待执行，不因模板文本存在而获得通过状态。

## 4 场景执行方式

1. 下载候选 MadB 和模板，核验摘要；不借用开发者工作区中的 Wrapper、二进制、缓存或绝对路径。
2. 每个场景在全新输出目录执行同一公开命令。记录人工前置步骤和工具自动执行步骤。
3. 使用真实 IDE 环境测试导入、索引和运行。优先采用稳定的官方自动化接口；缺少可维护接口时保留版本化人工复核步骤、执行人及证据，不能以 CLI 测试代替。
4. Lab 用独立预期检查示例结果，并执行源码变更、错误注入和恢复。模板自己生成的断言不得作为唯一 oracle。
5. 删除可再生构建目录、关闭 IDE，重新打开再构建；在最终输出路径和重定位路径分别执行。
6. 采集环境、版本、构建日志、设备结果、IDE 验证记录、耗时和来源摘要，写入模板认证报告。

`--verify run` 执行模板指定的运行冒烟，设备/模拟器由明确配置选择；不自动使用生产设备或上传项目。初始化是否打开 IDE 与 Lab 的 IDE 交互验证是两项操作。

## 5 主线门禁

S1 至 S4 各平台模板至少完成 INIT-01、02、03、04、06、07、08、09、10、11、12 的适用场景；对宣传支持调试的语言，INIT-05 同为必需。库模板的 Run 使用消费程序，应用模板使用实际应用界面。

初始支持可限定精确 IDE、宿主和目标组合，但必须公开限制。`structure` 模式是有效用途，不构成该模板“可运行”认证。S5 发布时所有推荐模板必须有覆盖其公开承诺的有效证据；不能把原生工程可用性延后到可选 IDE 向导阶段。

## 6 新用户实验

由未参与模板实现的开发者按首页说明创建并运行工程，记录手工接线次数、首次成功时间、失败定位时间和重试步骤。目标是在已准备工具链的环境里手工接线为零；系统 SDK 下载、协议接受和开发者签名时间单独统计。未完成基线实验前不承诺固定分钟数。
