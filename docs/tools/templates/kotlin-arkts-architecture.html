      同一 SDK 可以按接口混合使用。下方策略切换展示职责变化，不执行真实传输。

      受支持的类型形状

      类型化参数 / DTO

      Kotlin 类型与公开声明
      ↓
      后端转换 / 代理 / 引用
      ↓
      ArkTS 类型化 SDK

      适合明确的小型参数、公开对象和宿主接口。仍需处理复制、代理身份和寿命；直接传对象不等于零拷贝。

      显式协议选择

      受检 JSON 消息

      类型 / Schema 定义字段规则
      ↓
      编码 → 调用桥传 string → 解码
      ↓
      校验后的 ArkTS 数据

      适合显式消息和兼容协议。生成校验，不以类型断言代替检查；JSON 不解决 env、线程、取消或释放。

      大载荷 / 批量数据

      字节缓冲 / 二进制

      ByteArray / 明确的 native buffer
      ↓
      已验证的 buffer 转换与寿命
      ↓
      ArrayBuffer / TypedArray 外观

      声明复制、借用或转移、长度和释放器；检查偏移与分离状态。后端不支持时报告缺口，不能默认零拷贝。

      必须保留的语义设计与生成规则典型验证
      整数 / ID完整 64 位值选择受支持的 bigint 或受检字符串；number 只用于声明的安全范围。业务 ID 与运行时句柄分开。转换前检查范围；禁止先丢精度再转字符串；旧 env 句柄与收窄值拒收。
      空值 / 缺字段null、undefined、缺字段、默认值分别定义。未知字段与未知变体按版本策略处理。字段组合、非法标签、错误类型与超长载荷负例；转换失败不得变成合法空值。
      enum / sealed / 泛型按后端、方向和类型位置验证；必要时生成显式标签与字段投影，不使用 toString 作为协议。每个带数据分支保真；目标 ArkTS 类型限制与真实编译单独检查。
      Flow 与状态流由订阅协议表达；每帧可携带 DTO、JSON 或字节。状态与事件分别定义回放、合并、顺序和溢出。同步首帧、慢消费者、重新订阅；编码失败、拒收和投递失败分别执行声明策略。
      错误与业务阶段区分业务失败、协议错误、环境失效、取消与工具错误；保留“已入队 / 已受理 / 已完成”。回调异常与 pending exception；重复终态、超时后成功、工作已产生副作用。
      线上 DTO 与 ArkUI 观察实例分开。官方文档说明：装饰对象的 JSON 序列化可能包含观测用字段，反序列化得到的普通对象也不自动恢复观察能力。MadB 生成纯载荷转换，再更新已创建的状态实例；不把装饰器内部字段当作协议。ArkUI 官方说明

      04双向调用与退出时序

      同步方法保持明确的阻塞等级；以下异步场景展示线程投递与生命周期责任。

      开发者使用普通方法与观察对象

      以下是拟提供的 API 形态示意。方法名、类型和生命周期接入以最终生成契约为准。

      // 示意：普通 SDK，不暴露 napi_env 或原生指针。
const observation = client.observeState(
  (state: ScreenSnapshot) => {
    viewState.apply(state);
  }
);

const result = await client.send(command);
// result 明确表达 accepted / completed 等业务阶段。

// 页面观察 owner 发起停止：
observation.requestStop();
// 在可等待、由 owner 管理的收尾入口确认：
await observation.awaitStopped();
// 共享 engine 继续由应用 / 业务 owner 管理。

      低门槛增强不隐藏真实语义

      • Promise：只表达异步结果，不自动拥有取消或后台执行能力。需要取消的操作保留显式请求入口。
      • 观察令牌：关联订阅、generation、env 与 owner。是否保留后台观察由策略决定。
      • ArkUI：V1 / V2 分别适配；页面可见、隐藏、销毁与 Ability 前后台分别映射。
      • 装饰器：用于声明或状态观测；构建期生成必需字段与适配方法，不依赖任意动态改写对象。@Trace 在这里指属性观测。
      • 状态共享：一个页面退订只结束自己的观察；共享 StateFlow 上游由 scope、共享策略与其他消费者决定。

      05内存、线程与环境必须一起建模

      所有权明确到业务资源、操作、订阅、缓冲与回调引用。引用存在不代表能从任意线程使用。

      每个 env 一份上下文

      ArkTS 执行环境 / owner 线程拥有该 env 的句柄作用域、回调与允许的 UI 调度入口。
      EnvContext / 注册表关联 env 身份、存活状态、订阅 generation、引用与回投队列。
      Kotlin 协程 / native 工作线程携带受管 native 数据与操作身份；不直接携带临时 napi_value 操作 ArkTS。
      受检回投使用目标 SDK 与后端允许的 TSFN / 事件循环机制，返回所属 env 后再创建和调用 ArkTS 值。

      如果某后端仅支持主 env，就明确限制为该配置；不能给一个全局 env 变量加锁后宣称多 Worker 安全。[平台机制]

      Open → Closing → Closed

      Open→Closing→Closed
      • 关闭准入：阻止新调用、注册与回投，取消本 owner 的观察和可取消任务。
      • 排水收尾：等待获准回调、在途数据和任务按协议收尾；迟到结果释放一次。
      • 释放配对：在允许的环境和线程上清理引用、句柄与调度对象，再解除依赖。
      • 环境销毁：进入失效状态后不再访问该 env；剩余 native 工作由独立 owner 保活与收尾。
      • 超时：保持真实的 Closing / Invalid 状态，不以超时作为提前释放仍在使用内存的许可。

      引用不是业务生命周期

      unref、删除引用、停止观察、取消工作、关闭引擎分别处理；避免把一次引用计数操作当作全部清理。

      回调寿命覆盖在途调用

      注册可能同步回调。先建立上下文再启用来源；停止完成前保留所有获准调用需要的引用。

      排水不能堵死回投线程

      不在 env 线程阻塞等待必须回到该线程的清理；回调内关闭不等待自己结束。

      失败要封闭在边界

      检查平台状态与 pending exception；语言异常按契约转错误或进入失效状态，不能继续带病调用。

      06工程落地：模块、构建与交付

      同一条路线的 Kotlin、ArkTS 和 native 制品必须配套。主线易用性随 S3 交付。

      锁定目标组合

      CPF Kotlin、KSP1 与 akinterop 配套组件；SDK / API Level、ABI、DevEco / hvigor / ohpm 与 ArkUI 能力。升级组合单独探针。

      提取与生成

      导出面、桥注册、类型声明、受检载荷、SDK、状态和生命周期接线；生成来源可定位。

      编译与封装

      CPF 独立 Gradle 根构建 KN .so；平台工具编译 ArkTS / native 并形成 HAR / 原生依赖包。官方线另用独立坐标及元数据发布。

      真实 HAP 消费

      独立工程安装候选，检查注册、装载、调用、UI、环境退出、设备与 Release。

      原样发布与升级

      类型声明、库、运行依赖和符号摘要成组冻结；通过后发布同一内容，升级重新核对兼容与证据。

      主线与扩展各自验证装载、注册和候选身份。CPF / akinterop 的 Gradle、KSP 与生成入口成套固定；KNOI 扩展另检查依赖 .so 预载与总 sharedLib 注册入口。模板显式配置库名和初始化；Lab 用真实 HAP 验证，示例版本不自动成为 MadB 版本锁。KNOI 接入说明
      模块责任与实现方式生成 / 手写边界
      helpers / contractsReader 提取源码、KSP / 后端元数据，建立带来源与精度的契约。复用既有声明；缺失的所有权、线程、取消和恢复策略由作者指定。
      model / rules / plan纯核心；检查能力、类型、生命周期前提与版本，生成任务图。无 IO、无平台全局对象；不决定业务是否重试、何时清空草稿。
      generators / 后端适配Adapter / Strategy 默认接 CPF 配套 akinterop；KNOI 独立适配。按契约生成 DTO、codec、声明与注册接线。字段有单一来源；不重复实现上游绑定；复杂领域投影保留明确手写点。
      sdk/arkts + sdk/kotlinFacade、操作与订阅状态机、BufferAdapter、ExecutorAdapter、必要资源保护。普通 API 与便利语法共用实现。底层工作停止、业务同步与 native 安全仍需作者保证。
      sdk/arkts/ui小型 ArkUI V1 / V2 适配；生成本地状态类、绑定入口和生命周期模板。观察实例更新与协议解码分开；不把装饰器或类型断言当作实例转换。
      toolchains / templates / idemadb init、Gradle 与 hvigor 接线、DevEco 导入、注册、装载和混淆规则。复用既有构建计划；不覆写用户代码；不靠作者机器的绝对路径或私有缓存。
      verification / artifacts / Lab契约测试、真实消费、竞态、性能与制品身份；Packager 和 Store 分权。测试 oracle 独立于生成器；生成成功、目标编译、设备通过分别记录。

      单一职责

      调用桥、编解码、订阅、UI 与发布按变化原因分开。

      依赖倒置

      核心依赖稳定契约，后端差异留在适配器与目标配置。

      组合与状态机

      能力按需组合；注册、关闭、取消和结果交接有明确状态。

      显式能力失败

      不支持的类型或环境给出来源诊断；不静默改用 JSON 或减弱协议。
