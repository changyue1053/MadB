# MadB 总体架构

MadB 采用契约驱动的构建工具与轻量语言运行时协作架构。公共核心以 Rust 实现，外部生成器、编译器和语言元数据工具经端口接入；这一实现选择见 [ADR-0002](../adr/0002-core-and-adapters.md)。

## 系统组成

```mermaid
flowchart LR
    Init[一键初始化与工程模板] --> Project[原生 IDE 工程与构建接线]
    Project --> Author
    Author[SDK 作者的接口与语义] --> Read[读取与规范化]
    Read --> IR[边界模型与能力匹配]
    IR --> Check[纯规则检查]
    Check --> Plan[任务计划]
    Plan --> Backends[生成器与工具链适配器]
    Backends --> Package[语言 SDK 与原生制品]
    Package --> Consumer[业务应用]
    Package --> Lab[独立 MadB Lab]
    Lab --> Evidence[版本化证据]
    Evidence --> Gate[发布判定]
```

构建链路中的 JSON 是工具协议和报告格式，与 SDK 运行时的数据载荷选择无关。生成器内部表示也不构成用户必须学习的新业务 IDL。

## 构建时职责

读取器从 Rust 元数据、Kotlin 导出面、C/C++ 头或明确桥接声明获取结构。规范化器合并带来源的行为策略；能力求解器检查选定路线能否表达这些结构与语义。纯规则层输出问题和缺口，计划器生成有依赖的任务图。

路线选择依次考虑目标运行时、调用方向、接口能力、交付形态和配套构建系统。语言对只用于查找候选，不能直接决定后端。例如已有 C ABI 可以继续供多个语言消费；Swift/C++ 源码共同构建与面向外部的普通 Swift SDK 使用不同工程配方。选择结果属于已解析配置和 ProjectPlan，不把平台判断分散到公共核心。[选择决策](../adr/0008-route-selection-and-distribution.md)

适配器执行外部生成、编译、探针和验证。生成物、原生库、运行时、包元数据形成不可拆分的交付集合。发布判定读取 Lab 结果，不能把“命令执行成功”直接当成 SDK 可消费证明。

官方 Kotlin 与 CPF 分别构建、首版分别发布坐标，由模板映射依赖；Android 原生构建与已有原生库包装分别组织。Apple 制品还须满足生成后端的分发设置和消费者构建条件。具体配方集中在[构建发布](09-build-packaging-release.md)与[初始化架构](14-project-initialization.md)，架构总览不另维护一套版本表。

## 运行时职责

```mermaid
flowchart LR
    User[业务代码] --> API[语言惯用 API]
    API --> Semantic[生命周期与异步协议适配]
    Semantic --> Binding[现有绑定后端]
    Binding --> Native[原生实现]
    Native --> Callback[受管回调入口]
    Callback --> Semantic
```

语言 API 可通过委托、协议扩展、属性封装器、宏或生成方法改善使用方式。语义适配负责声明过的关闭、结果交接和观察协议。绑定后端负责实际调用与表示转换。原生算法、领域重试、认证和事务逻辑不进入公共运行时。

已有绑定后端能可靠提供的内存机制继续复用。MadB 只补充缺失的协议，不在每条边外再无条件加一套句柄、引用计数或线程池。

## 工程边界

MadB 发布工具、配置 schema、后端接入、必要的 SDK 运行时和模板。MadB-Lab 发布参考消费工程与验证资产，按工具版本和制品摘要执行。工具内部单元测试留在 MadB；黑盒消费断言由 Lab 维护。

工程初始化是应用层对模板、文件、环境探测及既有生成/构建用例的编排。ProjectPlan 维护模块、文件与 IDE 入口，ContractIR 继续维护边界语义；无需为初始化新增应用运行时。具体边界见[初始化架构](14-project-initialization.md)。

多语言元数据帮助程序可使用所在生态的实现语言，通过版本化的请求/响应文件或进程协议通信。默认不加载未知的原生动态插件到核心进程。进程分隔提供故障与依赖隔离，但不等于安全沙箱；其工作目录、输出路径与可执行文件来源仍受策略控制。

## 关键质量属性

- 可维护：核心规则不依赖外部工具，语言差异收敛在适配器。
- 正确：结构和语义均可追溯，未知能力显式拒绝或标为缺口。
- 可重复：输入、工具和输出可计算摘要；失败不提交半套产物。
- 易用：模板与安全默认值减少配置，语义错误在生成前暴露。
- 可扩展：新增语言、运行时或路线通过扩展清单、小型端口和符合性套件接入；现有模型可表达时不增加核心语言分支，出现新公共语义时版本化演进模型。

性能与发布条件分别见[诊断和性能](10-diagnostics-and-performance.md)、[构建发布](09-build-packaging-release.md)。

## 语言扩展边界

扩展包是适配器与资产的交付单元，运行时语言和工具宿主语言相互独立。Language、Runtime、Route 为开放身份；类型、所有权、线程和取消仍由受检的公共模型表达。

宿主经清单与锁解析组件，在组合根绑定端口，再协商协议、IR 和必需功能。ArtifactPackager 准备候选内容，宿主 ArtifactStore 校验后提交，独立 Lab 产生消费证据。任何扩展声明都不能直接成为认证或发布授权。

详细设计见[语言与后端扩展](11-language-extension.md)、[扩展进程协议](12-extension-protocol.md)及[核心模型演进](13-contract-evolution.md)。

[MadB 工程骨架](02-modules-and-ports.md)维护六个核心 crate、应用端口、CLI bootstrap、适配器与受控 host 的职责；[MadB-Lab 骨架](../validation/02-lab-architecture.md)维护真实消费者和独立预期。系统图的箭头表示调用或交付关系，源码依赖以模块规范为准，不据图中的 app→适配器调用推导 app 可导入具体后端。生成源码、构建产物和发布候选分别提交，语言 SDK 与工具宿主各自管理生命周期。
