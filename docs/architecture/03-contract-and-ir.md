# MadB 契约模型与中间表示

契约把接口结构、行为语义和平台实现能力连接起来。中间表示 IR 是内部模型；用户继续使用 Rust、Kotlin、C/C++ 等原有声明，不另写一份完整业务 IDL。

## 信息权威源

| 信息 | 来源 | 处理规则 |
|---|---|---|
| 函数、字段、参数、类型 | 编译器导出、绑定元数据、明确桥接声明或头文件 | 每条边界指定一种权威入口 |
| 释放、线程、取消、交付阶段 | 源语言注解或独立策略 | 同一属性只能有一个权威来源；冲突报错 |
| ABI 布局 | 对应目标的编译器探针 | 必须携带 target、宏、编译选项与库摘要 |
| 业务序列化协议 | 明确选择的 wire schema | 只在真正存在序列化协议时使用 |
| 支持能力 | 后端声明和版本化认证记录 | 声明与测试结果分别保存 |

源文件扫描适合定位和提示，不能冒充完整语义解析。精度至少区分 compiler-derived、artifact-derived、schema-derived、heuristic；无法建立安全映射的启发式结果不能进入自动安全包装生成。

## 核心模型

| 模型 | 关键字段 |
|---|---|
| Boundary | id、provider、consumer、direction、source、profile、target |
| Symbol | source_id、public_id、source_location、shape_digest、参数和返回类型 |
| Type | 标量宽度/符号、nullable、record、variant、buffer、resource、callback |
| Policy | ownership、releaser、borrow_scope、threading、cancellation、delivery、close |
| Capability | route、runtime、direction、versions、target、artifact_kind、build_system、supported_features、restrictions |
| Observation | subject、kind、precision、input_digest、producer、result |
| Finding | rule_id、severity、locations、reason、suggestion |
| Gap | required_evidence、subject、reason、blocking_scope |

IR 保留后端差异：不能把固定线程降为“串行”，把资源与值对象合并，或把未知枚举变体直接丢弃。泛型只在支持且已实例化或后端原生支持时进入导出面；其余给出明确诊断。

## 语义的必要字段

- 资源：创建方、关闭责任者、释放器、共享方式、依赖资源、关闭及销毁线程。
- 缓冲：元素类型、长度单位、编码、可变性、所有权、借用有效期、容量上限。
- 调用：同步/异步/流，阻塞等级、执行位置、返回表示的阶段。
- 回调：是否可同步触发、是否可重入、调用线程、context 保活者、注销与排水方式。
- 取消：请求接口、停止效果、确认事件、等待取消后的收尾责任。
- 事件：状态/事件分类、排序域、队列容量、溢出策略、回放与恢复方式。

策略族用于复用常见组合，但每个符号解析后都得到确定的有效策略及来源图。选择器零命中、意外多命中、符号变化导致策略不适用时立即报错。

## 配置选择维度

语言对只定位路线目录，不能独自决定可用的配置。能力匹配同时检查运行时、调用方向、接口需求、交付形态和构建系统，再解析配套工具链。模板组合和发布计划持有工程细节，ContractIR 只引用与边界有关的确定配置，不包含 IDE 工程文件。

| 维度 | 必须区分的情况 |
|---|---|
| 运行时与目标 | Kotlin/JVM 与 Kotlin/Native；ArkTS 的 Node-API 与 ANI 环境；官方 Kotlin 与 CPF |
| 调用方向 | 消费提供方接口、提供宿主回调、导出任意反向模块是不同能力 |
| 接口需求 | 普通值、资源对象、异步、同步反调、流、外部类型及所需停止协议 |
| 交付形态 | 源码共同编译、预生成包装、独立二进制 SDK；已有 C ABI 与双方可修改的桥接面 |
| 构建系统 | SwiftPM、Xcode、Gradle、Hvigor、Cargo、CMake 的实际生成、链接和反向导出能力 |

检查结果必须覆盖完整组合。例如 Swift 编译器支持 C++ 互操作，并不自动证明 SwiftPM 模板支持 C++ 消费 Swift API；生成 nativeMain 也不代表该生成器的 Gradle 插件支持 CPF/OHOS。运行时、版本或接口能力变化后，原配置证据不能直接继承。[后端配置](06-backend-profiles.md)保存具体限制，[工程初始化](14-project-initialization.md)据此选择模块配方。

## 处理顺序

1. 读取项目与锁，发现权威入口及目标。
2. 如元数据依赖编译，先执行单独的 metadata 构建任务，固定其输入和输出；不依赖尚未生成的消费端 SDK。
3. 读取结构，解析策略来源，产生候选 IR。
4. 校验类型、策略完整性和完整配置的后端能力，明确拒绝未知强制条件；多条配置满足时按已声明模板选择，不按安装顺序猜测。
5. 固化 ContractSnapshot，生成和验证都引用同一摘要。

策略默认值必须来源明确。调用方没有声明跨线程安全时，不默认生成 Send/Sync/Sendable；异步输入缺少保活策略时不默认借用。

## 协议版本与信任边界

配置、IR 导出、插件协议、报告、manifest 分别带 schema 标识。破坏性结构变化提升对应主版本；未知必填语义不能忽略。带命名空间的扩展容器仅保存非语义元数据；后端配置单独校验，必需语义通过版本化功能明确协商。

项目文件和帮助程序输出都视为不可信输入：限制大小、深度和路径范围；工具调用采用参数数组，不拼接 shell；工作目录和输出根显式传递。插件内容仍需可信来源和版本锁，进程隔离不等价于权限隔离。

[配置样本](../examples/madb.example.toml)用于固定写法。最终 schema 的实现与正反例必须作为同一工作项交付。

Language、Runtime、Route 采用开放标识；类型和策略的行为仍受公共规范约束。新增语言的普通映射留在适配器，无法由现有 IR 表达的公共语义按[模型演进规范](13-contract-evolution.md)处理。协议结构和 IR 语义独立协商，兼容某个协议版本不等于可以忽略未知类型或功能。

## 元数据准备与只读查询

源码、编译元数据与 ContractSnapshot 通过输入摘要关联。inspect/check 只读取新鲜快照；过期或不存在时返回 MetadataRequired 及明确的 `build --task metadata --frozen` 前置任务，不把编译器副作用藏在查询命令里。纯源码读取可直接产生快照，但仍报告其精度。

plan 可以先返回 metadata 准备图；准备完成后再生成完整任务图。metadata 子图不得依赖待生成的消费 SDK，避免“需要绑定才能读到用于生成绑定的结构”的循环。构建/验证再补充动态观察；未知限制是 Gap，不能因为静态规则未命中便视为通过。

## 符号身份与策略解析的确定规则

以下规则适用于首链及后续读取器，属于 DEC-01。`source_id` 定位源声明，`public_id` 定位 SDK 的公开能力，`shape_digest` 判断形状变化；三者不能互相替代。

- `source_id` 由读取器的版本化规范产生，包含包/模块、声明种类、限定名和重载判别；禁止使用行号、内存地址或编译器本次运行的临时 ID。无法稳定区分的声明必须要求作者提供明确桥接声明。
- `public_id` 在同一 SDK 命名空间内唯一。默认从受检源身份确定性派生；需要跨源重命名保持身份时，由作者显式指定稳定 ID 或维护重命名映射。保留 ID 不代表签名或行为兼容，仍检查相应摘要。删除的公开 ID 不复用于不相关能力。
- 首版策略选择器只接受完整 `public_id` 或读取器给出的完整 `source_id`，不支持模糊名字、正则、通配符或按声明顺序匹配。名称简写仅作为查询提示，不作为可提交策略。零命中、多命中、重复公开 ID 都在生成前拒绝。
- 解析顺序固定为读取声明 → 建立身份 → 展开声明选用的策略族 → 绑定显式语义 → 对缺项应用允许的默认值 → 校验并保存来源。策略族是默认值集合，不是第二份业务接口。
- 同一属性出现两个显式权威来源时，即使当前值相等也拒绝；作者应删除其中一处或把它改成只读验证信息。两个策略族提供相同属性也拒绝，不能靠优先级猜测。一个显式值可替代一个默认值，最终来源及被替代默认值均可追溯。
- 值类型输入可按 profile 采用复制默认值；线程安全、原生停止能力、释放器和业务成功阶段不从名字推断。必要信息缺失产生定位到声明的 Finding/Gap。

正例：两次读取同一声明得到相同身份；移动源码行只改变来源位置。反例：新增 `open` 重载、改名未提供映射、两处声明不同释放器时准确阻断。验收见 CRIT-07。

## 格式权威、摘要与首链 payload

DEC-02 采用 JSON Schema Draft 2020-12 作为对外文件结构权威。宿主和帮助程序的 DTO/解码器从同一 schema 生成，或以同一组格式向量验证；内部领域类型可以手写，但不能另立一份 wire 字段定义。状态机、身份引用和能力检查属于语义验证，不能用 schema 通过替代。

首链集成必须交付以下字段契约及正反样本。它们复用现有端口，不增加业务 IDL；C02 的完整 schema、受检转换与共同向量见[格式实现](../schemas/README.md)，实际源读取器与扩展进程接入继续由 C05/E01–E03 完成。

| 对象 | 首链必需信息 | 拒绝条件 |
|---|---|---|
| ContractSnapshot | schema、source_digest、structure/policy 摘要、已解析 profile、符号及来源精度、必需功能 | 未解析目标、重复身份、未知必需语义、过期输入 |
| ReadRequest / GenerateRequest | schema、边界身份、输入引用及字节摘要、锁定组件、profile、输出根 | 错端口格式、缺身份、输入与快照不一致 |
| OutputSet | generation_id、input_digest、task_digest、profile_digest、文件相对路径/大小/摘要、声明来源 | 重复路径、未声明文件、文件缺失或摘要不符 |
| BuildTask / BuildEvidence | 任务与依赖、固定输入、工具与参数、输出及实际执行阶段 | 依赖环、未跟踪输入、错目标、把编译当成运行 |
| PackageRequest / Candidate | 已完成输出引用、锁、契约与策略摘要、公开文件/依赖/符号、验证要求 | 混合批次、缺运行依赖、重新构建后沿用旧证据 |
| VerifyRequest / VerificationResult | 固定候选、Lab revision、解析后的案例实例、预期、实际结果与清理证据 | 未实例化案例、缺身份/证据、任意崩溃冒充负例通过 |

语义摘要采用带域标识的 SHA-256：`SHA256(UTF8(domain + "\n") || JCS(semantic_projection))`。各域带格式主版本，例如 `madb.contract/1`、`madb.policy/1`。JCS 采用 RFC 8785；这是新语义投影的编码规则，不改变既有清单、输入文件或制品按实际字节计算 SHA-256 的规则。[JCS 规范](https://www.rfc-editor.org/rfc/rfc8785)

投影先展开默认值；集合按稳定 ID 排序，参数/字段布局/有意义的事件顺序保持原顺序。64 位及更大整数常量使用带类型的规范十进制字符串；精确浮点常量使用带宽度的位模式字符串，避免 JSON number 丢失精度、负零或特殊值。一般 JSON number 只用于受 schema 限制的安全整数。缺省、null 和空集合的含义由字段定义，不能统一删除。

结构摘要包含公开形状与 ABI 相关属性；策略摘要包含有效语义；生成任务身份再加入 profile、后端/补丁、模板、工具及依赖输入摘要。源码位置、时间、绝对工作区路径不进入语义投影；源文件字节与逻辑相对路径进入 source_digest，运行证据仍绑定实际输入。字符串保持原值，不静默做 Unicode 规范化；文件逻辑路径统一分隔符并按目标文件系统检查别名冲突。

首链至少验证键顺序变化不改变语义摘要、参数顺序变化改变摘要、仅来源行变化不改变形状摘要、策略或工具变化使对应缓存与证据失效。序列化实现必须通过共同向量，不用宿主语言默认 map 顺序计算身份。

`generation_id` 由任务身份与按路径排序的输出文件清单生成内容摘要，不使用时间或随机值；清单不把自身作为被哈希输出，外层候选再记录清单文件的字节摘要。会话 ID、日志和运行时间单独放在执行记录，避免循环哈希和非确定性生成。

## C02 的格式实现入口

[格式与投影 v1](../schemas/README.md)固定 SourceKey 的长度编码、15 类业务文档、离线解析预算、精确数值、语义投影、来源诊断和拒绝边界；[首链 ABI](../examples/first-route/README.md)固定状态值及关闭的声明形状。领域模型保持独立，wire 到 domain 的转换位于 `adapters/contracts`，真实 IO 和用例装配由 C04/C05 接入。schema、纯规则或声明编译通过均不代表路线已认证。
