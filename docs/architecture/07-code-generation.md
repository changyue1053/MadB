# MadB 代码生成与自动化边界

生成器处理可以由契约机械推导的代码。业务决策、原生算法和无法证明的同步假设保留为显式实现或约束。

## 可以生成的内容

| 内容 | 前提 |
|---|---|
| 类型、参数和返回值接线 | 类型映射存在且来源精确 |
| 输入校验、错误适配、稳定标签转换 | 范围和错误分类已声明 |
| 资源包装、释放调用 | 释放器、转移点、线程和失败策略齐全 |
| 回调注册、context 保活、取消接线 | 后端具备相应停止与排水协议 |
| 强类型 ID、有限 DTO 快照 | 投影、复制深度和读取隔离明确 |
| Gradle/SwiftPM/原生构建接入片段 | 工具链和包布局已锁定 |
| schema 校验器与来源映射 | 明确选择 wire 协议并支持所用方言 |
| 注解/宏入口、可观察状态和惯用 API 外观 | 语言工具支持、公开语义明确；与普通入口复用同一协议 |

不能从签名猜出“发送已受理”“取消会撤销”“此指针线程安全”。无法安全生成时定位缺失语义，提供实现接口或模板；模板中的必填方法在完成前不能作为可发布 SDK。

## 流水线

ContractSnapshot → 完整配置能力匹配 → 类型/语义 lowering → 后端生成与声明检查 → 固定生成批次 → 目标构建与消费探针 → 候选包。各 profile 的实际无环依赖决定 metadata、声明编译、链接和运行节点的位置。

lowering 保留 source map 和语义责任链。优先调用成熟生成器；MadB 自研范围是约束模型、胶水、受限投影及后端缺少的特定机制。每个变换都可独立单测，最终正确性由真实消费者验证。

语言层采用 KSP、后端宏或构建期生成时，薄层只提取声明、传递元数据或生成对普通 API 的调用。KSP 不读取/改写函数体，语法宏不被当成线程安全证明。错误要追踪到作者声明，重复导出与冲突语义在生成前阻断。工具选择、依赖与普通 API 回退见[语言特性设计](15-developer-ergonomics.md)。

## 后端生成配方

| 场景与权威输入 | 生成产物 | 必须保留的边界 |
|---|---|---|
| Kotlin/JVM 消费受限 C 声明，或明确的 C++ 桥接声明及策略 | Kotlin `external` 声明、JNI 签名、`JNI_OnLoad/RegisterNatives` 注册表、参数/错误转换、资源和回调包装 | 裸指针、借用、线程附着及 C++ 异常封闭必须有契约；注册名与 R8 保留规则一起生成 |
| 大量既有 C++ API 需要 Java/JNI 接入 | 可选 SWIG Java/JNI 后端及受限接口描述 | 独立声明支持的类型、重载、director 回调和打包条件；不承诺任意头文件自动得到安全 API |
| 已有 C ABI 或多语言共享的 C 可见面 | bindgen 导入、cbindgen 头文件或目标语言包装，按提供方分别选择 | 头文件与导出实现的权威关系明确；不能用新生成声明掩盖实际布局或符号漂移 |
| Rust/C++ 双方可控制且采用 CXX 支持的桥接面 | CXX 绑定与编译接入 | CXX 是此配置的实现，不自动替换已有 C ABI |
| 既有 UniFFI Rust 接口增加 ArkTS 消费者 | 实验性的 UniFFI-ArkTS 绑定、序列化辅助代码与 OHOS Node-API adapter | 复用已声明接口，独立锁定兼容版本；不与直接 napi-ohos 导出或其他 UniFFI 版本任意混用 |

JNI 默认生成受限接线，不另造通用 C++ 解析器。`JNI_OnLoad` 中注册失败应尽早报错，导出符号、类加载器与线程规则由对应 profile 管理。[Android JNI 指南](https://developer.android.com/ndk/guides/jni-tips)、[SWIG Java/JNI](https://www.swig.org/Doc4.4/Java.html)

后端模板也是需审查和锁定的代码。Gobley/UniFFI 的 foreign future 重复完成修复必须落到实际生成模板，并验证成功完成路径抛异常时不会再走第二次完成；只升级 Rust runtime 不足以证明修复生效。补丁身份、生成代码摘要及对应回归证据一起进入发布记录。[上游修复](https://github.com/mozilla/uniffi-rs/pull/2733)

## 受控进程与结果准入

C04 的 `ProcessRunner` 是宿主内部端口；[扩展协议](12-extension-protocol.md)中的 E02 JSON Lines 会话另行实现。一个 `ExecutionControl` 只能启动一次；取消先原子关闭结果准入，重复取消幂等，先完成的结果不被迟到取消回滚。这里的 `EligibleForValidation` 只授权继续解析和验证原始结果，不授权发布。

| 责任 | 执行规则 |
|---|---|
| 启动与身份 | 工具绝对路径、字节大小/摘要前后核对，工作目录通过目录描述符检查；参数数组、清空继承环境再设置白名单；固定 `subprocess 1.2.1` 的 execve 路径，ENOEXEC 返回失败，不隐式交给 shell |
| 输入输出 | stdin、stdout、stderr 同一循环非阻塞读写；有限输入、stdout 超限终止、stderr 有界保存并报告截断，持续输出不能饿死取消检查 |
| 终止与回收 | 先 SIGTERM，再按宽限升级 SIGKILL；WNOWAIT 保留 leader 到最后一次组信号结束，再回收，避免复用 PGID；macOS 的 EPERM 必须复核 leader 已退出且组内没有其他成员，查询失败保留缺口 |
| 清理证据 | 分别记录直接子进程回收、两条输出管道 EOF、组终止尝试与信号错误；任何清理缺口阻止结果准入。未回收句柄随结果保留，调用方继续 poll；Drop 仅尽力处理，不能当完成证据 |
| 后续事务 | 进程结束后仍需 payload/schema/身份检查、请求取消状态与输入复核、对应提交层的短锁/CAS；任务/候选不由原始 exit 0 自动变为 ready |

工具和工作目录必须由宿主管理且在整个调用中稳定；前后核对不是对抗恶意同权限写入者的安全快照，也不包含解释器、动态库、sysroot 等完整依赖。指定脚本的解释器仍属于工具链信任与输入追踪范围。宿主必须是这些子进程的唯一 waiter，禁止 SIGCHLD 自动回收和竞争的 `waitpid(-1)`；ECHILD 诊断不能消除其他 waiter 造成的检查后复用竞态。

`timeout` 从成功启动并设置管道后计时，结束阶段另有清理预算；启动前后文件 IO、OS 启动和依赖解析不受该计时器约束，不能对外承诺整个调用的硬实时上限。受控目录应使用正常本地文件系统。被阻塞的系统 IO、脱离进程组的后代、关闭管道后继续的外部工作仍需更高层隔离/协议约束。

Linux/macOS 的进程组不是安全沙箱；本地 leader 与管道收尾不证明任意派生进程树或远端副作用停止，也不限制网络。E02 的停止确认、输出事务和完整依赖闭包仍有独立验收。[真实进程回归](../../tests/integration/c04_process/README.md)覆盖平台差异、畸形工具和清理缺口。

## 已声明输入副本与运行目录

固定输入分为两层，均不改变 source_digest 的权威定义：

| 层 | 已实现的约束 |
|---|---|
| app 的 FrozenInputs | 清单先校验再读取：1～4096 文件、每文件 ≤32 MiB、总量 ≤128 MiB、≤32 路径组件、≤8192 父目录；只接受规范 ASCII 相对路径，拒绝重复、目录组件大小写别名和文件/目录祖先冲突 |
| 捕获与复核 | 按声明大小限制读取，逐文件检查字节摘要/大小；完整捕获后再次读取比较，失败不返回部分快照。快照私有字段，克隆共享不可变字节，源文件后续变化不修改它 |
| host 的 PreparedRun | 在调用方授予的稳定 parent 下独占新建单层目录；既有文件、目录、链接一律不覆盖。以目录描述符和 NOFOLLOW 创建 inputs/work；inputs 文件 0400、目录 0500，work 及运行根以 0700 创建（受 umask 约束） |
| 实际执行 | 工作目录必须为 work，配方显式使用 ../inputs/...；不猜测或重写 argv。执行前后检查声明文件及全部父目录的精确集合，并拒绝缺失、额外项、链接、硬链接和非普通文件；复核位于取消/结果准入完成之前 |
| 保留责任 | 准备成功后只有一个运行目录 owner；执行消费 PreparedRun 返回 RetainedRun，保留进程观察、诊断和待回收句柄。准备失败在已经分配目录时返回 retained_path；未分配时不声称拥有既有路径。所有目录默认保留，Drop 和 poll_cleanup 不删除，也不授予安全删除资格 |

诊断分工：INPUT001 为清单结构，INPUT002 为预算，INPUT003 为初始字节不符或缺失，INPUT004 为已捕获字节复核失败；初读宿主错误保留 HOST 码。INPUT005 为运行目录准备失败（打开 parent 时保留原 HOST 诊断），INPUT006 为副本集合/运行根身份异常。执行层将副本验证错误附为 EXEC017，已有进程故障保持首个诊断；两者都不能取得结果准入。

本层的字节副本只表示**声明的文件**，尚未记录未声明依赖、目录发现集合、缺失文件条件、解释器和动态库。因此不能以它启用确定性缓存或声称完整依赖闭包。顺序双读不是文件系统原子快照；只有最终由固定副本消费的已声明字节被确定。只读权限防误写，前后核对不能证明没有 ABA 修改，也不阻止同权限工具读取任意绝对路径、网络或逃逸。

源文件变化后旧快照仍可独立执行，但后续提交必须复核当前输入/CAS，不能覆盖新结果。运行目录可能仍被关闭管道的逃逸后代使用；清理协议与安全回收另行实现，测试 harness 仅在停止其已知辅助进程后移除自有目录。真实用例见[固定输入回归](../../tests/integration/c04_inputs/README.md)。

## 单任务配方与结果字节

C04 的首个执行入口是内部 Rust 单任务 API。contracts 读取既有 BuildTask、project/request/IR/profile/lock 并形成受检配方；app 保留任务参数、环境、声明输入和输出；host 准备私有副本并运行。静态 TaskGraph 不包含完整执行配方，不从它反推工具或参数。单任务入口只接受空 dependencies 和 work 工作目录，不忽略依赖，其自身不承担正式 CLI 或事务；正式阶段编排见本页后文。

| 边界 | 当前规则 |
|---|---|
| 任务身份 | task_digest 复用完整 BuildTask 的既有规范投影。input_digest 表示受检 IR 的来源链，匹配 IR.source_digest；task.inputs 是该任务实际使用的文件清单，独立逐项捕获，不要求两个清单摘要相同 |
| 批次身份 | generation_id 关联请求声称消费的既有批次，不预先填入本任务未来输出批次；本次只做身份配对。批次真实性、来源和提交权限仍须后续事务验证 |
| 工具安装 | 所选 profile.tools 的工具必须被 lock.tools 完整锁定；宿主注入安装后相对路径、大小和 image 摘要。component 的包/清单摘要不能充当 image；仅 components 命中不支持执行 |
| 参数责任 | task.arguments 是本次完整 argv，保持顺序；profile.tools.arguments 参与配置身份，不由通用宿主自动拼接。必需目标 flags 由具体配方生成与对应 profile 消费验证负责，不能由“包含某个字符串”代替 ABI 验收 |
| 配方协议 | stdin 为原始 BuildTask，stdout 为 BuildEvidence；沿用既有 schema，无 E02 帧或会话。普通编译器通过显式配方适配，不要求原生编译器理解 MadB JSON |
| 结果准入 | 实际零退出、无诊断、直接子进程/管道收尾与无 pending owner 后才校验 payload；非 passed、错身份或退出码、错输出集合均拒收。helper 自报状态不替代宿主观察 |
| 文件捕获 | outputs 与 logs 合并预检预算、路径及别名，再读取/复核真实大小和摘要；工作目录只能有这份清单及其父目录。捕获为不可变字节；以后磁盘变化不改变已接收值 |
| 取消与保留 | 解析、文件捕获、精确目录检查及最终输入复核都在一次性 gate 关闭之前；取消胜出不暴露结果值。失败保留原始进程与目录，后续 poll 不升级准入状态 |

配方声明的日志文件只证明对应字节存在；原始 stdout/stderr、退出与清理观察以 ProcessRun 为准，不从日志文字推导成功。结果验证失败转换为 EXEC018，保留原始诊断 cause；输入或运行目录变化仍沿用 EXEC017。准备失败不启动进程，已经分配的目录继续返回 retained_path。

返回的受检任务结果是可继续验证的观察，不是 ready SDK、已提交批次或完整依赖证明。源树、生成批次来源、传递依赖、当前索引/CAS 和实际消费语义仍各自验收；保留目录和固定字节不能代替这些条件。

## 静态串行图与依赖结果

C04 内部图入口在同一受检 project/request/IR/profile/lock 上绑定所有 BuildTask，共享解析校验器；不为每个节点重复构建完整 schema registry。图绑定输入文档总量最多 16 MiB，单文档仍受 1 MiB 限制；静态全图最多 4096 节点，实际选中执行最多 64 节点。此图原语与正式 CLI 阶段编排分开；E02 会话仍按独立工作包实施。

| 责任 | 执行规则 |
|---|---|
| 图与配方 | ExecutionGraph 包含不可变绑定配方，TaskGraph 只表达拓扑元数据。先校验全图重复身份、依赖、循环与输出归属，再选择 named target 的依赖闭包。普通单任务入口不能接收带依赖配方 |
| 来源分类 | 完整图中有 output owner 的输入只能来自该 producer，并要求显式直接依赖。缺边、自身同路径读写、前缀大小写别名或文件/目录冲突均拒绝；选中子图不能改变来源分类 |
| 外部源 | 仅合并所选节点的 external source，同路径必须具有相同大小/摘要。首节点前一次捕获；之后节点输入从固定源与已验证依赖结果组装，不重新读取活动源 |
| 依赖产物 | 只接受同次图执行、直接依赖已捕获的 outputs；不接受日志、旧运行回执或活动 work 文件。预期 hash/size 不符即失败，不回退同名外部文件 |
| 执行次序 | 确定性拓扑顺序、串行、首次失败即停止后续节点。命名子图只启动目标及其依赖；不并行、重试或继续独立失败分支 |
| 图级取消 | GraphControl 独立一次性准入；注册当前节点、取消和最终接受共用短锁，锁内不做 IO。每节点独立 ExecutionControl；当前节点已经完成但整图未结束时取消仍能拒绝图结果 |
| 结果与 owner | 每节点结果立即移交给图，原始观察与目录 owner 继续保留。只有整图验证成功才公开结果集；失败/取消丢弃值而保留现场和 pending owner。清理 poll 不升级图终态；目录不自动删除 |
| 字节预算 | 根源与所有节点输入副本在首节点前预留，加上累计 outputs/logs 最多 256 MiB；每节点既有文件数、深度、单文件 32 MiB/合计 128 MiB 限制不变。剩余结果预算在文件读取前检查，不能先过量捕获再拒绝 |

命名子图不豁免未选中节点的绑定、输入身份一致性或图结构规则；执行时只按选中消费者的预期身份检查 producer 结果。未选消费者的运行时预期不能阻断单独指定的 producer，但完整图执行仍会在 producer 接纳时提前拒绝不匹配。合并后的外部源清单也遵守 FrozenInputs 的 128 MiB/文件数量等限制。

当前静态图要求每个输入摘要与大小在绑定时已知。不知道未来产物身份时，先执行发现阶段，取得真实身份后绑定下一张图；不能执行中静默补写 BuildTask 或改变 task_digest。工具传递依赖的完整发现仍是后续工作，当前结果不提供缓存或提交资格。

宿主先独占分配图目录，再用 node-0000 等索引创建节点目录，不把逻辑任务 Id 当路径。预取消可以留下空图目录，但不准备节点、不启动进程。部分准备失败返回已分配目录；已存在的目录不被认领或覆盖。文件读取/准备可能同步完成后才响应取消；上述预算不限制工具任意磁盘写入、网络或 RSS，私有目录也不是同用户安全沙箱。

图诊断沿用稳定代码与原始 cause：DAG001 表示图结构或准入错误，DAG002 表示图预算，DAG003 表示依赖或节点结果不可接纳；TASK003 表示结果超过当前剩余预算。具体准备/进程/文件诊断保留于节点观察，不用图摘要替换原始错误。

## 受管输出、构建任务与提交

DEC-04、DEC-05 将生成源码、构建产物和发布候选视为三个提交层级。生成源码完整不等于已链接，编译成功不等于可发布；每层都有独立清单和状态。

| 层级 | 发布到下一层前的检查 | 失败处置 |
|---|---|---|
| 生成源码批次 | 全部文件、来源、语法/声明检查；执行不依赖循环产物的编译探针 | 保留上一个完整批次；staging 不成为有效输出 |
| 构建产物批次 | 固定输入批次、目标编译与链接、公开消费端编译/调用探针 | 不产生 ready 候选；不能拿旧库搭配新头文件 |
| 候选包 | 公开文件、依赖、锁、身份及指定验证要求完整 | 宿主拒绝提交；已验证候选保持不可变 |

每个 profile 提交自己的无环任务图。需要 native 元数据的读取器先执行独立 metadata 子图；不能依赖尚待生成的消费 SDK。声明编译、链接和运行分别设节点，依赖二进制的消费探针放在对应构建之后，不能统一要求它们在源码提交前完成。独立的暂存编译可以先执行，但其缓存和带暂存绝对路径的二进制不直接作为最终制品。

生成前列明受管文件；只写独立 staging，校验相对路径、重复/大小写别名、越界和链接逃逸。文件内容落入不可变版本目录，索引一次指向一个完整批次。消费者在一次构建开始时固定 generation_id 和目录，后续不反复追踪会变化的 current；现有批次的最后一个读取租约退出后才可回收。

同一工作区的同一输出域只允许一个提交者，输出域由实际受管目录确定；两个 target/profile 写同一目录时属于同一域。不同域可以并行计算。提交只持短锁：核对任务仍可提交、输入快照未变、索引代次符合预期，再原子更新索引。索引变化时，只有完全相同输入和输出身份才可复用已有批次；其他结果返回 GenerationConflict 并重新计划，不能后完成者覆盖先完成的新输入。

文件写完、摘要确认和持久化后才更新索引；崩溃恢复读取已提交索引，完整孤儿目录可清理，部分目录不进入消费。平台适配器必须证明本地文件系统的原子替换及恢复行为，不把任意网络共享盘默认为支持。无条件目录覆盖、多个语言各自切换 current、跨进程长持全局锁均不符合协议。

运行外部构建时不持有子任务可能申请的提交锁。TaskGraph 拒绝递归调用同一应用构建；IDE 与 CLI 调用同一命名子任务。构建可消费自己固定的完整批次，但其结果若与当前输入已不一致，只作为该旧快照的产物保存，不能替代当前 ready 索引。模板接入见[初始化架构](14-project-initialization.md)，竞态验证见 CRIT-09。

## 输入追踪与确定性缓存

DEC-06 使用分层身份：source_digest 记录真实输入，结构/策略摘要记录语义，任务键加入完整 profile、工具/补丁/格式化器/模板、参数和依赖；文件及制品摘要按字节校验。语义规范化由[契约规范](03-contract-and-ir.md)统一定义。

每个 reader/toolchain 输出依赖清单，至少包含实际读取的源文件与传递 include、宏/cfg/feature、目标 sysroot 和头来源、编译链接参数、工具摘要、白名单环境。目录扫描或可选文件发现还须记录路径集合及缺失文件条件，避免新文件出现却仍命中旧缓存。涉及 SDK 或编译器隐式搜索路径时记录其确定身份；无法可靠列举输入的任务先禁用缓存或采用保守重建。

C/C++ 优先复用编译器依赖文件和 bindgen 读取回调；Cargo 使用构建脚本变化声明，Gradle/Hvigor/Xcode 接入实际输入输出。构建系统的变化探测触发 MadB 复核输入，不代替 MadB 的内容摘要与完整性检查。[Cargo 构建脚本](https://doc.rust-lang.org/cargo/reference/build-scripts.html)、[Gradle 增量构建](https://docs.gradle.org/current/userguide/incremental_build.html)

首次发现依赖时用收集到的完整依赖重新确定任务身份，再决定是否复用缓存。提交前复核输入；编译工具不能稳定读取活动源树时采用输入快照目录，不能把混合修改前后内容的输出标为确定结果。缓存恢复逐项验证清单和摘要，损坏时重建；网络解析与构建分离，frozen 不隐式升级。

`generate --check` 在自有临时目录复算，与已登记批次比对缺失、修改、多余文件和登记差异，不修改源码、锁或有效输出。默认只读已有依赖缓存，缺项返回准备任务。随机工作目录下相同输入的文本必须逐字节相同；二进制可重复性单独测量。间接头变化、宏变化、文件增删、缓存损坏和源树在生成中改变的验证见 CRIT-10。

## 显式输入观察与图末复核

除后文受限编译器依赖发现外，C04 也提供独立的调用者声明输入观察。`InputWatchSet::new(absent, directories)` 与 `InputObservation::capture/verify` 不含文件系统实现；`ObserveWorkspace` 在 host 读取存在性和有界直接成员。它们没有新的 wire schema、任务摘要或可缓存标记。

| 条件 | 语义与边界 |
|---|---|
| 已声明文件 | 复用所选图的 external source FrozenInputs；图末复核内容，不因文件 mtime 未变就接受。不会重新读取上游活动 work 来替代固定结果 |
| absent | 整条路径没有入口才匹配；末段 dangling symlink 也算存在；中间链接、非目录、权限错误不等于缺失 |
| 目录成员 | 完整直接成员的名称和 File/Directory 类型，排序比较；不递归，不追踪未声明成员内容；拒绝链接、特殊节点、硬链接普通文件和不支持名称 |
| 一致性 | 观察目录与后代文件可共存。捕获的直接成员须满足已声明存在后代的首个子项，不能遗漏；缺失声明与实际成员冲突、跨清单大小写别名或类型矛盾均拒绝 |
| 预算 | 最多 4096 absent、256 目录，声明前缀至多 8192；所有目录合计 8192 成员、2 MiB 名称，剩余额度在 host 分配前限制、app 返回后复核；合并实际成员后的前缀至多 16384。路径 ASCII、32 层及 LogicalPath 长度约束保持 |
| 命名子图 | 自动复核文件只限所选 external source；显式 watch 原样应用，不从所有配方猜测，也不自动删除所谓无关观察 |

`execute_graph_observed(graph, source, watch, executor, control)` 与原 `execute_graph` 分开：后者允许源在捕获后变化而继续完成旧快照；前者在同一 GraphControl gate 内依次检查声明、捕获观察、固定源、复核观察、执行图、复核源与观察，最后才接受结果。预取消不做读取；新增读取窗口中的取消仍可拒绝图结果，错误或取消保留节点 owner，已移交的结果值不从节点泄露。

最终复核失败可能发生在所有节点已经执行之后，拒收不会撤销工具副作用。同步读取不承诺可中断；新增/删除后恢复原状的 ABA 不一定可见。工作区根按打开的目录描述符固定，调用方负责稳定根路径；顺序复读不是原子文件系统快照，成功也不是提交授权，未来仍须在提交窗口复核。

watch 不复制目录成员、不自动扩充 task.inputs；工具真正需要读取的文件仍须明确声明。运行目录应位于观察源目录之外，否则自身生成目录也会构成观察变化。目录和 optional-header 搜索的完整集合最终由 reader/toolchain 发现，不通过当前观察集合推导闭包完整。

OBS001 表示观察结构错误，OBS002 表示观察预算，OBS003 表示条件不符或复核失败；图末已声明文件变化沿用 INPUT004。初次 host 读取保留 HOST002/HOST003；复核错误保留其文本，并以冲突拒收。不变的 wire/task_digest/source_digest 仍不包含新观察，禁止据此建立持久化缓存或批次来源声明。

## 验证责任

golden 测试验证输出形状，编译测试验证可编译，行为测试验证契约。消费编译探针必须引用承诺交付的公开符号，识别 SKIE 等后端生成的 `unavailable` 占位；运行测试再验证真实调用结果。预期行为不能从同一份生成逻辑生成。每个后端还要验证非法输入、重新生成、失败恢复和手写扩展保留。

## C04 正式阶段编排与存储协议

`madb.execution/1` 只组合现有端口，不把生成任务伪装为 BuildTask。metadata 直接运行 ReadRequest→ContractIR，不依赖待生成 IR；generate 运行 GenerateRequest→OutputSet；build 在真实 generation_id 已知后绑定 BuildTask 图；package 运行 PackageRequest→Candidate。所有命令要求显式 frozen 配方，自动推导各语言后端仍由后续路线实现。

生成配方必须在返回成功 OutputSet 前完成该语言的语法/声明检查。C04 的锁定 C fixture 真实调用 Clang 对最终输出执行声明检查，并以错误声明负例验证拒收；宿主的 exit 0 和清单校验不构成任意语言的语法证明。C05 的具体 generator adapter 负责落实各语言检查。构建提交至少需要成功的 compile、link、run 阶段；未覆盖的命名子图只报告已执行，不提交完整构建批次。候选必须引用固定 source 中的真实 OutputSet 和固定 build 中完整的 BuildEvidence 集合，禁止从外部目录补入同格式自报证据。

| 状态/身份 | 实施规则 |
|---|---|
| 内容身份 | 源码、构建、候选各自的元数据和文件构成不可变内容身份；wire generation_id、candidate_digest 继续按既有投影计算 |
| 物理批次 | 每次物化获得独立 instance；坏文件重建不覆盖旧目录。索引/父引用指向 instance，同内容复用前仍验证实际字节 |
| 层级切换 | 新 Source 清空 current Build/Candidate；新 Build 清空 current Candidate。子批次必须匹配父 instance、source lineage、profile 与 generation |
| 输出域归属 | `.owner.json` 以 `madb.storage-owner/1` 认领。首次只接受空目录；无有效标记的非空目录零写拒绝。初始化短锁防首次并发竞争 |
| 提交 | staging 在锁外写入并同步；受管域短锁内检查父链、expected revision、输入和取消，原子替换 current。大文件生成及外部进程不持提交锁 |
| 租约和恢复 | 固定批次同时持有祖先链读取租约。writer lease 在初次分配锁内建立，恢复不会删除活跃 staging。显式 recover 只按已提交索引恢复，遇未知名称/类型先拒绝而不猜测删除 |
| 发布后错误 | `STORE008` 表示索引已替换，之后持久化或回执不确定；先检查 current 再决定是否重试，不能解释为“从未提交” |

`PipelineControl` 的结果准入延续到提交或只读检查结束，子图结束不会关闭它。错误/panic 的 scope guard 关闭未完成操作；SIGINT/SIGTERM 通过宿主监听线程调用取消，异步信号处理器不执行锁和清理逻辑。[signal-hook 接口](https://docs.rs/signal-hook/0.4.5/signal_hook/iterator/type.Signals.html)

取消先关闭提交准入，再请求活动子进程停止；提交已胜出则后续取消返回已完成。取消结果拒收与进程清理是否完整分开记录，失败保留原始执行诊断和目录。CLI 退出时仍未完成的回收只能尽力处理，不宣称所有逃逸后代已停止；不额外引入后台守护进程。

只读 check 使用已有 store，不创建 owner/lock/cache；缺批次或损坏明确失败。其临时运行目录遵循现有保留策略并报告位置，不自动删除仍可能被逃逸进程使用的目录。普通执行的 store/run/cache 不得重叠，不能覆盖源或配置；显式观察条件、源搜索域同样在首次创建目录前校验，防止缓存和运行目录成为自身输入。

本实现验证 Linux/macOS 本地文件系统上的进程崩溃恢复。原子替换与 fsync 顺序不是网络文件系统或所有断电行为的认证，恢复也不会根据“最新目录”猜测有效结果。

## C04 受限原生依赖准备

`build --task dependencies --execution <file> --frozen` 使用显式 `dependency-request`，验证选中 profile 和 lock 中的真实 Clang image，返回独立 `dependency-manifest` 及预处理结果。后续配方必须显式纳入清单内精确文件引用并重新计算自己的任务身份；工具不修改原请求。已保存 receipt 只提供输入复核材料，不能反序列化成新的可缓存证明。

| 维度 | 当前可证明的配置 |
|---|---|
| 工具与目标 | 原安装位置的 ELF/Mach-O Clang；显式 target 为 arm64-apple-macos11.0、x86_64-apple-macos10.15、aarch64-unknown-linux-gnu 或 x86_64-unknown-linux-gnu，与 profile ABI 族匹配 |
| 搜索范围 | 源文件须有显式父目录；源父目录和 include 目录递归冻结全部有界文件，另记录实际 `-M` 读取子集。全域是保守输入上集，避免仅剪裁 depfile 文件改变 `__has_include` 语义 |
| 配置 | 固定 `--no-default-config -nostdinc -Werror=date-time --target`；只接受受限 `-D/-U/-std/-x` 参数，环境仅 LANG、LC_ALL、SOURCE_DATE_EPOCH |
| 拒绝项 | 动态/计算式 include、外部绝对/上跳搜索、token paste、pragma、modules、embed、trigraph/digraph 及不支持的编码/路径；续行归一化后仍执行限制检查 |
| 真实观察 | 对有序翻译单元执行两组真实 `-M`，规则、成员和对应 source 必须一致；复核固定输入与目录条件。原生准备执行 `-E -P`，时间宏展开失败不写入缓存 |
| 缓存 | key 覆盖格式/provider、目标、配置上下文、工具、参数、环境、完整搜索域字节、实际 discovered 集合、目录成员及 absent。每次查找先取得新的受支持发现结果，逐项校验存储文件，损坏视为 miss 且保留坏数据 |

预处理缓存只服务这个固定原生准备配方；任意 helper、脚本解释器、Cargo/Gradle 或系统 SDK 的未知依赖不会因此获得完整性。系统运行库和安装工具链仍是需保持稳定的受信宿主条件，不把 image 摘要说成通用执行环境沙箱。未知配置拒绝该缓存路径，其通用显式配方仍可按自身合同无缓存执行。

准备上下文使用版本化长度编码包含 dependency request、lock、profile 原始字节，排除 receipt，避免自引用。receipt 的文件/工具/目录条件在消费与提交前再次校验；实际编译器被替换而锁未更新同样拒绝。普通 `generate --check` 只读取已准备 receipt，缺项给出准备任务，不启动发现或写缓存，但仍真实复算生成配方。
