# MadB 运行时与语言惯用 API

运行时采用三层设计：共同的语义协议、按需的语言原语、符合性验证。后端已经正确承担的机制直接复用，MadB 仅增加有明确职责的包装。

## 组件

| 组件 | 责任 |
|---|---|
| ResourceLease | 操作准入与资源保活；不创建新的业务 owner |
| OperationBridge | 一次完成、取消请求、结果交接和后台收尾 |
| SubscriptionBridge | 注册、限流、停止投递、排水及上下文释放 |
| ExecutorAdapter | 按声明执行线程或环境投递 |
| ErrorAdapter | 保留错误分类、取消与失效信息 |
| BufferAdapter | 受检长度、复制/借用/转移及释放配对 |
| UI Integration | 页面观察生命周期与状态更新入口 |

这些是职责单元，可由后端能力直接实现，不要求每种语言出现相同类层级或重复引用计数。

## 一次完成与结果交接

OperationBridge 必须把结果计算/转换与向外完成通知分开：交接前失败可以进入失败结果；完成责任已经交出后，通知函数抛异常不能再次调用成功或失败完成函数，也不能再次释放已交接资源。后续异常按约定诊断，不改写已提交的结果。

该约束必须在实际后端模板或其受控适配层实现。外层 Promise 的一次兑现机制不能证明 native 完成回调只执行一次。验证覆盖成功通知抛异常、重复 native 完成、取消与结果竞争、迟到结果释放，并检查对象、缓冲及回调上下文最终只清理一次；生成器升级与运行时升级分别记录证据。

## 各语言外观

| 语言 | 候选外观 | 必须保留的语义 |
|---|---|---|
| Kotlin | suspend、Flow、use/Closeable、属性委托、扩展函数 | CoroutineScope 归属与原生停止效果 |
| Swift | async/await、AsyncSequence、协议扩展、属性封装器 | actor 隔离、资源 owner、停止确认 |
| ArkTS | Promise、类型化方法、监听令牌、适用的状态装饰器 | env、UI 线程、生命周期与退订 |
| Rust | Result、Future、Stream、Drop、受限 newtype | Send/Sync 前提、借用与显式异步关闭 |
| C++ | RAII、move-only handle、明确状态返回 | 析构约束、异常策略、线程和回调寿命 |
| C | 不透明句柄、内联校验、成对关闭函数 | 调用方责任、明确长度、线程与释放配对 |
| Dart 扩展探针 | 同步类型化调用、复制值、显式关闭 | 仅 E04 同步子集；Future/Stream、反调与 UI 属于另行声明的扩展 |

上述外观只有在对应后端和版本通过验证后才发布。属性包装器、宏或装饰器不隐式创建全局 scope，不把多次视图构造变成多次原生注册。

普通方法和类型是稳定使用面，便利语法按需启用并复用同一语义实现。属性 getter 读取已同步的本地状态，不隐式执行阻塞 FFI 或建立订阅。语言特性、生成工具、依赖分层及示例以[专题设计](15-developer-ergonomics.md)为准。

## UI 接入

Compose、SwiftUI、UIKit、ArkUI V1/V2 分开提供小型适配层。生命周期状态包括首次绑定、可见、不可见、销毁、前后台切换；各框架映射到统一观察协议，但不假定每个框架事件完全等价。

页面通常拥有观察令牌，应用或业务层拥有共享引擎。页面退出可以等待观察停止，不能顺手关闭其他页面使用的引擎。对需要保留后台观察的业务，使用显式策略。

输入同步适配携带 revision、origin、编辑状态等业务允许的元数据，避免旧快照覆盖新输入。输入法组合态和“受理后清空”必须由真实 UI 案例验证；工具只能执行声明策略，不能替产品决定草稿丢弃时机。

## 语义适配例子

同一个观察协议可在 Kotlin 暴露 Flow，在 Swift 暴露 AsyncSequence，在 ArkTS 暴露 Subscription。三者共同保证停止完成后不再调用该消费者；各语言取消上层等待不自动等价于关闭共享数据源。

冷 Flow 的每次收集可以拥有独立 native 观察；共享 StateFlow 的上游停止由 SharingStarted、其他消费者和 owner 决定。取消一个页面的收集不能默认注销共享数据源。非挂起清理回调只能发起停止；需要等待的排水由明确 owner 管理，确认接口与“停止请求”分开。

Kotlin 向 Swift 导出简单 DTO 时可直接用导出类型；需要 ID 类型安全时加 Facade；需要独立数据所有权时生成快照。快照只包含声明支持的字段，复杂对象和循环引用需要显式投影。

## 发布约束

运行时包与生成代码建立兼容区间；修改状态机和停止保证同时更新行为版本。运行时只携带该 profile 必要组件，不携带编译器、CLI 或无关平台代码。扩展点提供协议实现接口，并要求运行同一符合性套件。

必需的资源准入、所有权交接、线程约束和状态机保护在诊断关闭时仍然生效。指标、日志和追踪是可选出口；验证同时覆盖普通入口、便利入口及未插桩 Release。

## 投递与结果包装的实现边界

SubscriptionBridge 的投递票据覆盖 native 入口、执行器排队和用户调用；执行器内原子认领准入，再运行用户代码。停止后排队项只能清理，不能再次进入页面。OperationBridge 分开管理“终态已认领”和“资源已由调用方接收”，具体转换见[生命周期规范](05-lifecycle-and-concurrency.md)。

包装只检查自己建立的代次、登记和能力。无法验证任意裸指针有效，不能承诺拦住外部绕过包装的访问；公开的安全保证必须注明受管入口及原生实现前提。

## 每种配置的机制责任表

DEC-07 要求 resolved profile 附上按符号和语义阶段分配的责任表：类型转换、输入保活、终态通知、结果接管、观察注册、停止、线程投递和最终释放分别指向一个实际组件及其锁定版本。它由 lowering 计划产生，并由核心检查唯一责任；不要求作者重复声明上游元数据已经明确的事实。

上游完整实现某项保证时标记 delegated 并复用；MadB 只补缺失步骤，记录交接点和符合性用例。外层 Promise 不能替代 native 一次完成检查；再次包装已完成的模型转换也不能成为默认路径。SKIE + NativeCoroutines 的 X01 配置按接口关闭重叠协程桥，类型增强可独立复用。

SDK 作者声明必要语义，普通消费者只使用稳定方法、资源对象和状态 API。便利层不拥有第二套订阅/取消状态机，构造和 getter 不启动原生工作。UI 编辑 revision、origin、输入法状态留在选用的 UI 适配器，不进入所有边界都必须携带的业务模型。

## 执行器与容量的默认配方

DEC-08 的调度配置引用显式 owner；复用调用方提供的执行器或该 SDK 实例持有的执行器，不隐式创建进程全局线程池。串行、固定 OS 线程、actor 和 env 能力分别匹配。

- 同步接口保持其声明的调用位置；不能为了线程切换把同步返回静默变成异步，也不能用同步等待模拟不受支持的跨线程反调。已知等待环或回调内等待自身关闭时拒绝。
- 任务队列必须有项数和保留字节预算，单个载荷有上限。具体数值随 profile 负载测量并写入锁；缺预算不能进入推荐配置。超限在取得接管责任前返回 ResourceExhausted；已接管资源必须完成合法清理。
- `state` 可显式选 capacity=1、coalesce-latest，替换旧项时归还其载荷责任；`event` 满队列时，有同步返回通道的生产入口在接管前返回 ResourceExhausted；没有该通道的推送配置终止本次观察，并在观察终态结果中记录 ResourceExhausted，不静默丢弃或再次调用已停止消费者。只有 profile 证明生产者可阻塞时才允许阻塞背压。
- 关闭先禁止新业务准入，停止生产，再排水和执行环境专属清理，最后关闭执行器。收尾能力在接受任务时预留；控制/清理不能依赖已经满载且停止消费的业务队列，也不能无限扩张另一个清理队列。
- env 提前失效时不再调用其 API。需要 env 的资源必须在有效期内清理；只能在其他线程销毁的纯原生资源交给声明的 owner。无法提供该顺序的后端不获得强关闭保证。

普通接口、便利层和诊断关闭配置共用这些机制。CRIT-11 验证满载、重入、退出和释放线程，不能只统计正常调用吞吐。
