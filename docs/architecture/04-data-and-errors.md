# MadB 数据映射与错误契约

数据传递先满足信息保真，再选择适合调用方的表示。直接映射、Facade 和独立快照是三种可组合策略，不要求所有边界都维护三套模型。

Swift 生产 SDK 的范围与取舍按 [ADR-0014](../adr/0014-swift-production-baseline.md)落实；本文规定类型与错误，隔离和交接由[生命周期协议](05-lifecycle-and-concurrency.md)承担。

ArkTS 的必要公开类型与错误能力按 [ADR-0016](../adr/0016-arkts-production-baseline.md)落实，复用实际目标后端的表示。类型化值、ArkUI 可观察实例和 JSON 载荷各有转换边界；普通类型断言不能制造实例、校验数据或证明 native 对象身份。

## 类型映射规则

| 类型问题 | 规范 | 验证 |
|---|---|---|
| 数值 | 保留位宽、符号与范围；收窄必须检查 | 上下界、溢出、负值、非有限浮点 |
| 64 位整数到 ArkTS | 依据运行时选 bigint、受限 number 或明确字符串协议 | 大于 2^53−1 的整数不能静默通过 number 路径 |
| 空与缺失 | nullable、optional、默认值分别建模 | null、nil、undefined、缺字段分别测试 |
| enum/variant | 声明开放或封闭；使用稳定标签 | 未知值保留、拒绝或降级的行为明确 |
| ID/单位 | 业务 ID 与内存句柄分开；包装只提供类型保护 | 不用 ordinal、地址或调试字符串作为协议值 |
| 字符串 | 指明 UTF 编码、长度单位和 NUL 规则 | 多字节、嵌入 NUL、无效编码 |
| 集合 | 限制长度、嵌套深度和元素类型 | 空集合、大集合、递归对象 |
| 对象与快照 | 描述身份、共享性、复制深度和读隔离 | 修改源对象不意外改变独立快照 |

转换责任只分配一次。现有绑定已完成的转换不再机械包一层；需要强类型 ID 或真正独立值语义时，才生成受限 Facade/快照。Swift struct 内包含引用并不自动具有深度独立性。

Swift 普通入口优先复用满足公开类型与隔离契约的后端表示；跨 actor 传递所需的快照还须验证字段的可传递性、一致版本与复制深度。普通值和已取得独立所有权的值快照不增加 `close()`；带原生资源或共享身份的对象仍遵循其资源契约。

## 字节与零拷贝

默认可复制的值语义应具有明确性能预算。零拷贝是独立能力：必须证明地址存活、长度合法、别名规则、读写同步和释放路径。借用对象跨异步保留，只有受管 owner 或显式转移成立时才允许。

空缓冲在各语言内按合法表示处理。C 允许某接口使用 null+0，不意味着可以把它直接传给要求非空且对齐的 Rust 引用构造 API。输出参数先初始化为安全状态，只有成功并完成所有权交接后才暴露给调用方。

## JSON 与 wire 协议

JSON 用于明确的消息载荷或动态协议需求，不作为全局传递方式。使用时 schema 必须规定数值范围、缺字段、未知字段、标签、大小限制和兼容方式；两端生成相同约束的编码器和校验器。`JSON.parse` 后的类型断言不能代替运行时校验。

字节缓冲、类型化对象和 JSON 可以在同一 SDK 并存，但改变载荷表示属于协议变化，需要重新生成、验证和发布。

## 错误分类

公开结果区分：不存在、业务拒绝、调用取消、环境/资源关闭、内部故障。不同语言用其惯用 Result、throws、错误码或 Promise rejection 表达，保持分类可辨认。

Swift 的公开错误类型还须保留兼容与能力不匹配的类别，不能把取消、关闭、错库或不支持配置统一改写成业务失败。稳定类别、原因与恢复性是契约；具体 `Error` 表示可以复用后端，必要的薄映射不丢弃这些信息。

ArkTS 的 native 边界失败、宿主接口失败和页面监听器异常分别保留其来源与责任。Promise rejection 或外层捕获不能证明 native 已停止或排水；已经交出的完成通知不得因监听器抛错而再次兑现。具体受管错误与完成协议继续以 [ADR-0013](../adr/0013-arkts-runtime-and-completion.md)为准。

正常业务错误不能映射为 panic。未约定的 Kotlin 异常、C++ exception、Rust panic 或宿主回调异常在各自允许的边界内封闭。封闭方式由后端决定；不能假定 catch_unwind 捕获 abort 或任意外部异常，也不能假定 CXX 的 Result 机制处理所有 panic。

Swift 外观不承诺捕获任意上游 fatal/panic；无法安全恢复的上游错误不能包装成可恢复的普通 failure。后端已规定终止或对象失效的路径仍保留该后果，不能仅靠 `throws` 外观承诺调用方可以继续使用对象。

返回错误后明确对象是否仍可用：recoverable、invalidated 或 fatal。异常发生在部分修改之后时，恢复前提必须由原生实现给出，工具不自动承诺事务回滚。运行时错误处理、释放器和回调错误本身也要有失败策略。

## 发布前证据

TYPE 和 ERR 问题必须有边界值、非法输入、未知变体和宿主失败案例。底层指针、布局和异常细节来自目标编译器及后端契约，不能只靠宿主单元测试证明。对应问题见[问题目录](../validation/04-problem-catalog.md)。

## 按机制落实编码与快照

| 机制 | 必须写入配置的规则 | 独立反例 |
|---|---|---|
| JNI 字符串 | `NewStringUTF` / `GetStringUTFChars` 使用 Modified UTF-8；普通 UTF-8 要显式转码，或使用 UTF-16 长度接口 | 嵌入 NUL、补充平面字符、孤立代理项及非法输入按声明处理 |
| C 指针与长度 | 分开声明字节数、元素数、容量；检查乘法溢出，失败输出初始化 | null+0 合法性、超大长度、错误释放器；检查不证明任意地址有效 |
| Kotlin/Swift 独立快照 | 在指定执行器/锁下取得一致版本，复制深度覆盖可变引用；投影失败不交付半个快照 | 转换期间源对象改变，结果要么属于一个明确 revision，要么报冲突 |

JNI 的 UTF 接口不等于标准 UTF-8，不能全局套用一个字符串转换函数。[Android JNI 指南](https://developer.android.com/ndk/guides/jni-tips)

每个字段的映射责任只出现一次：后端已转换的表示由外观复用；额外复制和转码在来源映射及性能观测中可见。
