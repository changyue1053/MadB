# MadB 诊断 可观测性与性能

用户面对的是一次跨端调用，诊断应能把语言包装、原生实现和制品身份连接起来，同时控制采集成本与数据暴露。

## 构建诊断

诊断结构包含 id、severity、category、message、boundary_id、symbol、source_locations、target、evidence_precision、原因及建议。支持文本、JSON 和适合 CI/编辑器的 SARIF 输出。格式化不改变规则结论。

Finding 表示检测到的问题；Gap 表示证明某项能力所需的信息或验证缺失。环境失败与业务契约失败分开。错误码是兼容接口，面向人的解释允许改进；自动化不能靠匹配中文消息判断结果。

例：TYPE-001 指向整数到 number 的不安全转换，同时指出发生转换的字段、可能丢失的范围及可选方案。建议可以是受限范围、明确大整数表示或不同后端；不得自动改协议。

## 运行诊断

按需记录 operation_id、subscription_id、resource_id、阶段、执行器、持续时间、结果分类和包标识。ID 用于关联，不暴露裸地址。默认不记录业务载荷、密钥、完整用户标识或任意异常对象的内容。

生产构建默认提供必要错误报告和有预算的低成本指标；额外指标、回调轨迹和诊断性检查按需启用。用于正确性的准入计数、所有权交接、线程约束和状态机保护不受诊断开关控制。采样、上限及导出方式明确，避免诊断本身堵塞 native 回调线程。

崩溃符号化绑定二进制摘要、build ID/UUID 和符号包。日志和符号不匹配时显示 mismatch，不能给出貌似精确但来源错误的栈。

## 插桩策略

优先在生成边界加入可关联声明的诊断钩子。Android/JVM 字节码插桩属于目标明确的可选扩展，不能替代 Native、Swift 或 ArkTS 的机制；ASan/TSan/UBSan 和静态属性按工具链能力启用。ArkUI 的 `@Trace` 属于状态变化观测，不属于这里的调用追踪。

诊断 sink 失败、队列满和导出阻塞不得改变业务结果或破坏资源协议；使用有界采集和明确丢弃策略。生成钩子与字节码插桩避免对同一边界重复计数。工具依据见[语言特性与插桩](15-developer-ergonomics.md)，开关等价性和未插桩验证见[DX 套件](../validation/07-developer-ergonomics.md)。

契约检查、静态属性和运行插桩分别报告覆盖范围：缺释放器可由声明规则阻断；`lifetimebound` 等只帮助检查可识别的寿命关系；Sanitizer 只对支持目标和实际执行路径提供观察。不能把三者概括为任意跨语言内存与线程行为已经静态证明。S1 先交付边界诊断及开关对照，深度插桩仍按 L08 单独推进。

## 性能模型

| 对象 | 记录指标 | 典型工作负载 |
|---|---|---|
| 工具 | 冷启动、增量时间、峰值内存、缓存命中 | 多模块接口扫描与再生成 |
| 同步调用 | 延迟分布、分配次数、跨界次数 | 标量、小 DTO、大批量 DTO |
| 字节数据 | 复制次数、总复制字节、保留峰值 | 空、小、大缓冲和持续流 |
| 订阅 | 吞吐、端到端延迟、队列深度、丢弃 | 慢消费者、多生产者与取消 |
| UI | 线程占用、更新频率、输入响应 | 高频状态和列表更新 |

按 release 构建、固定设备/工具链、预热和重复实验记录样本。工具引入的开销与业务原生工作时间分开显示。先建立基线并获得稳定噪声范围，再设绝对预算或回归阈值；没有测量前不设毫秒或内存承诺。

零拷贝优化同时报告资源保留时间和别名约束；复制减少却显著延长大缓冲存活不必然更优。批量调用和减少全量状态更新通常先于复杂内存共享，但每项变更都依测量判断。

## 验收

缺少关键关联字段、日志包含敏感数据、符号不匹配误用、队列无上限、性能结果无环境信息，分别进入评审或发布阻断。性能不稳定的环境可报告观察结果，但不能替代受控基准通道。
