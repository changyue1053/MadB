# C07 ArkTS 四路线实施与验收

任务 C07 · 规范基线 0.9 · 起点 MadB `2a0d992e75e5198985ee4e383ca19cfc1f48ee6c`、MadB-Lab `c53a64ef2c160fa7ca9b8e23d6365b84d882fc41`。当前是实施与准入记录，尚无 C07 整包验收结果；状态以[任务目录](../catalog/implementation-plan.json)为准。

## 范围与责任

四条直接路线为 `KN-ARKTS-NAPI`（CPF-KMP-CMP + akinterop）、`ARKTS-RUST-NAPI`（napi-ohos）、`ARKTS-C-NAPI`、`ARKTS-CPP-NAPI`（平台 Node-API）。CMP 渲染、KNOI、UniFFI-ArkTS beta、ANI 和工程初始化保持各自任务范围。

复用 C04 冻结端口、契约格式及候选清单，路线特例留在 generator/toolchain adapter；语言 SDK 承担声明的类型、所有权、异步和环境协议。Lab 从公开 HAR/库/声明构建独立 HAP，不导入生产者私有源码。设备安装和执行属于独立 Lab，不直接放入会预执行再重放的 C04 构建步骤。

每路线需要一个能力明确的完整 profile，而非实现所有语言类型。拟用小型值类型、显式资源、异步操作、取消、state/event 和非阻塞通知验证边界；不强制沿用 C06 的同步 Host.transform。不能通过把异步、观察或退出清理全标 Unsupported 绕过必需验收。具体 API、预算和 profile 在 P05/P06 探针后冻结。

[napi 固定源码](https://github.com/ohos-rs/ohos-rs/blob/e4eb8e1b493d6c3aa98ca220776605963df8135a/crates/napi/src/env.rs)中的 async cleanup 包装，在用户闭包返回后即移除原生清理 handle。启动异步任务后立即返回不等于 drain；真正异步退出需显式持有原生 handle 至清理完成，或受管补丁，并验证无需等待已关闭的业务队列。

## 普通 ArkTS facade 与关闭确认接线

本切片把普通 Runtime/Engine/Operation/Subscription 模板及15项独立接线回归放入仓库。模板状态机是手写 SDK 运行时代码，生成器负责固定模块/独立身份替换、声明读取和一致性检查，不能宣称生命周期由类型自动推导。私有54字段诊断帧与唯一布局一并固定，测试拒绝 enum/layout 漂移。

独立审查实际复现并修复了三个问题：无 close 观察者时 native 已退休而 JS 未记录 Closed，导致重试和8槽复用失败；Runtime 先分配 timer 使 timer 失败阻断关闭请求；同步原生错误未统一到导出的 BoundaryError。现在关闭结果先锁存并经内部 kind2 ACK 送达，子资源先于 Engine；request-only 仍推进确认，原生 slot 不提前复用。关闭请求先于 timer/观察者准入，用户 getter/监听器异常保持原身份。要求已补入 ADR-0013。
