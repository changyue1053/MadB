# C04 整包交付与验收记录

## 任务与范围

任务：C04 整包收口，包含此前六个子范围及剩余完整输入、缓存、三层事务、正式 CLI 和故障恢复。依据：`ae290a7131b1e521d8c3e0109fb715332871cb41` 的 C04 acceptance、DEC-04/05/06、模块规范和 CRIT-05/06/09/10。分支：`codex/c04-complete-package`。

范围：madb-app 的用例与端口、contracts 的格式转换、host 的依赖发现/缓存/事务、CLI 组合根、对应测试与现行文档。保持已有 C02 格式身份定义；新增内部持久化格式须带版本并验证，不在 extensions 中隐藏权威字段。

不包含：C05 的语言生成器、SDK 生命周期及独立 Lab 认证、其他平台正式支持、远程缓存、仓库合并或发布。真实编译器探针验证 C04 的执行基础设施，不授予路线认证。

## 实施决定

- 生成、构建、候选保持三个提交层级；存储批次身份与 wire generation_id 分离。源码切换不保留与其不匹配的构建/候选 current。
- 操作提交使用独立的一次性准入控制，不能复用已经结束的图控制器。取消与最终索引切换具有共同的线性化协议；提交先胜出时不声称回滚。
- 同一实际目录属于同一输出域，短文件锁内复核输入和索引代次。工具运行、输出计算及大文件物化在锁外。消费者持有固定批次与读取租约。
- 首个可证明完整输入的发现实现为受限 freestanding Clang C/C++ 配置：实际传递依赖、声明搜索目录/缺失条件、工具、参数、宏及显式环境纳入身份；不支持的配置禁止缓存，不以用户布尔值或退出 0 声称完整。
- 依赖发现之后再绑定执行身份，消费冻结副本并在提交窗口复核。缓存只复用已验证字节，不能复用取消状态、提交权限或认证结果。
- `generate --check` 使用自有临时运行目录，重新计算并比较受管批次；不修改源码、锁、有效输出或只读依赖缓存。缺少准备材料给出明确准备任务。

## 验收方式

模块测试覆盖路径、预算、身份、状态与取消；真实多进程测试用确定性屏障覆盖旧结果、固定消费租约、并发提交和崩溃恢复；真实编译器与独立消费者验证输入失效；CLI 黑盒验证退出类别和只读文件摘要。完整门禁为 `.venv/bin/python scripts/check.py`，最终提交另核对远程 CI。

### 审查与边界

独立只读审查覆盖所有权认领、原子 current/CAS、祖先租约、取消与提交线性化、父批次证据、受限依赖闭包、缓存与只读检查。发现的目录认领、信号取消、续行规范化、目标/输入域检查及构建诊断问题已修复并补回归；当前范围内无未解决的 P1/P2。执行契约按 spec/artifact/build/dependencies/files/package 拆分，公开路径和原定义经逐项复核，拆分前后相同测试均通过。

macOS Arm64 上 `.venv/bin/python scripts/check.py` 全部通过：254 项 Rust 测试、216 项 Python 测试（含 68 项 C04 整包集成），另含 Node 摘要向量、隔离 CLI 安装、架构依赖和文档/HTML 检查。最后的诊断补丁另通过 CLI all-targets Clippy 和真实失败/取消测试；统一门禁的集成阶段覆盖该补丁。远程 Linux CI 待按 PR 提交核实，不以本地结果替代。运行目录保留、受信工具链/系统运行库、受限原生缓存、Unix 本地文件系统及未认证 SDK 的边界见 README 和生成规范。C05 的实际语言 reader/generator、完整资源协议及独立 Lab 验收不属于本记录。
