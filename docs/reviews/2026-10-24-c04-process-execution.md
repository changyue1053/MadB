# C04 受控进程执行子范围

任务：C04 进程端口与执行/取消准入。依据设计 0.9、模块边界、代码生成规范及扩展协议的进程责任；基线为已验证查询提交 `8d909aed0060aa1aece8a71046671f56d5e54dfa`，分支 `codex/c04-process-execution`。

范围：madb-app 的进程请求/结果和一次性准入；adapters/host 的 Unix 启动、有界非阻塞管道、超时、进程组终止与直接子进程回收；真实辅助程序及可控时序回归。普通 CLI 的只读命令维持原行为。本批不开放 build/generate，不实现 E02 JSON Lines 会话、源码/构建/候选提交或缓存，也不计 CRIT-06 整体通过。

实施约束：

- 调用方明确授予工具目录、工作目录和环境白名单。工具路径/摘要在启动前核对，结束后再核对；目录和安装文件必须由宿主管理且在执行中保持稳定。它不是恶意同权限写入者的防护沙箱，也不证明工具所有动态依赖已冻结。
- 参数作为数组传递，环境清空后只设置显式白名单项；没有 shell 拼接或 PATH 工具查找；使用固定 subprocess 1.2.1 的 execve 路径，畸形脚本/镜像返回启动错误，不触发 shell 回退。输入有限，stdout 超限终止，stderr 有界保存并记录截断；日志不自动向终端输出。
- 取消先记录“不再接收结果”，执行准入和结果接收各只发生一次。任务结果仍须后续端口验证及事务提交，进程零退出不等于 SDK 成功。
- 子进程单独建组；观察退出时保留未回收 leader，完成组信号发送后才回收，避免向复用的 PID/PGID 发信号。管道在同一执行循环中非阻塞读写，不用无法停止的日志线程。
- 正常/异常/取消/超时各有独立结果。直接子进程回收、管道关闭、组终止尝试分别记录；不将进程组等同 OS 沙箱或任意派生进程树。脱离进程组或不配合的外部工作不能据此证明停止。
- 清理超预算返回显式缺口，未回收子进程的句柄仍有 owner；不能伪造 cancelled 或提交输出。后续事务/E02 还须依据协议确认整个请求的停止后条件。

验收：现有 scripts/check.py、定向 Rust 准入/取消时序测试、真实子进程的参数/环境/工作目录/输入输出、错工具/启动失败/崩溃、日志洪泛、stdin 背压、超时/强制终止、派生进程持有管道与清理观察。结果在执行后记录；没有执行的不写通过。

## 平台差异与独立审查

真实 macOS 测试定位到只剩僵尸 leader 时组信号返回 EPERM；Apple 的 [XNU killpg1](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c)会过滤 SZOMB，空投递可返回该错误。实现不直接忽略 EPERM：先以 WNOWAIT 确认 leader 已退出，再使用锁定 libproc 按 PGID 观察；空组或只含该 leader 才接受，任何其他成员/查询错误保留缺口。它不证明逃逸进程停止。

独立审查复现了 std::process::Command 对畸形 shebang/伪 ELF 的隐式 shell 回退，文件头检查不足以阻止副作用。已删除这层伪保障，改用固定 [subprocess](https://github.com/hniksic/rust-subprocess) 的 execve 启动；四种真实负例必须同时证明失败和未创建标记文件。依赖的 detached 只取消析构阻塞，不启动回收线程，owner 仍唯一持有句柄。复核新启动路径、所有权与 EPERM 分支后未发现剩余源码阻塞；最终测试由本记录补齐。

宿主必须是唯一 child waiter，不启用 SIGCHLD 自动回收或竞争 waitpid(-1)。timeout 只覆盖成功启动/管道设置后的执行循环；前后目录/工具 IO 与 OS 启动不在该预算内。工具链全部动态依赖、强隔离和事务准入未由该切片实现。

## 验证结果与剩余验收

macOS Arm64，项目固定 Rust 1.99.1、Python 3.14.4/Node 环境下，`.venv/bin/python scripts/check.py` 全部通过：54 个 Rust 测试（新增 7 个准入/竞态/资源保留测试）、19 组真实进程测试、13 组只读查询、9 个架构正反例、5 个格式/ABI、6 个 C03 进程和 21 个文档测试，共 127 个测试函数。另通过共同向量、隔离 Release 安装、13 份 HTML 一致性及 DOM 替身检查。`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings` 与 `git diff --check` 通过。

四种畸形工具（普通文本、空解释器、空白解释器、伪 ELF）均得到启动错误且未创建副作用标记；真实 pipe 背压、取消、TERM/KILL、同组后代清理、逃逸后代保留管道的缺口，以及执行期间工具/目录变化均按独立预期通过。退出/取消竞争采用 Barrier 确定顺序，未回收资源用独立计数验证保留；无法强制构造内核不可中断状态，真实 D-state/OS 启动卡死未测试。

未修改 MadB-Lab、现有 schema、原生 SDK 或历史验收结果。没有新增 SDK/路线认证、E02 完成证据、整机沙箱、视觉验收或全事务 CRIT-06/09/10 通过声明。C04 保持 `in_progress / running`；下一步为固定输入与任务执行接入，再完成三层提交、CAS/恢复、完整依赖追踪和缓存。远端 CI 以交付 PR 的实际 head checks 为准。
