# MadB 文档与架构图质量规范

文档的质量标准是让开发者找到确定的机制、责任和验收条件。统一导航与视觉语言，内容按路线的实际差异组织；不规定每页相同节点数、卡片数或示例行数。

## 规范、计划与视图的责任

| 材料 | 权威范围 | 不能承担 |
|---|---|---|
| architecture / ADR | 行为与取舍；候选版本集中在技术栈规范 | 没有实验却宣称实现或认证 |
| catalog 的问题、路线与任务 | 稳定编号、范围、依赖、实际进度 | 用任务名称猜测测试覆盖 |
| route-views / HTML 模板 | 投影规范；说明当前配置的机制与案例 | 新增隐藏语义，关键词推导任务或认证 |
| reviews | 指定快照下做过的检查、遗漏与变更 | 作为后续新页面、新候选的通行证 |

一个视图配置不是已解析 boundary profile。视图的案例和伪代码不能直接作为后端真实函数签名；需要编译的示例必须单独标注目标、依赖和测试。

## 每个路线专题须回答

1. 谁提供能力、谁消费、哪个方向、哪个运行时？不能把正向调用当作任意反向导入。
2. 哪个编译器/生成器产生哪些代码、二进制、声明和运行依赖？生成与手写分别落到模块。
3. 哪些类型直接映射，哪里复制、序列化或保留对象身份？不强制三套模型。
4. 调用、回调和关闭分别在哪个线程/执行器发生？同步返回与异步投递不能用同一箭头含糊代替。
5. 注册、源端、排队项、用户回调和结果分别由谁保活，失败时谁释放？
6. 当前路线最有代表性的失败如何触发，独立预期是什么，关联哪个问题与实施工作包？
7. 源码共同构建与公开 SDK 分发需要什么不同证据，哪些能力仍须明确拒绝？

允许共用布局和已定义协议，不能把 UniFFI、JNI、C ABI、CXX、ANI 或工具服务的实现机制混写。对未知/不支持能力，图和时序直接显示拒绝，不仅在图外脚注提示。

## 三层检查分别记录

| 检查 | 可证明 | 不能证明 |
|---|---|---|
| 静态一致性 | JSON/TOML 可解析、引用存在、任务无环、问题映射明确、HTML 与输入一致、脚本语法及基础图形几何 | 布局美观、字体截断、浏览器行为、FFI 正确 |
| 独立文档工具测试 | 非法引用被拒绝、精简拓扑可接受、草稿/证据不混用等指定逻辑 | 真实浏览器交互或产品后端行为 |
| 真实浏览器复核 | 桌面/窄屏布局、滚动、主题、键盘、图形标签、配置切换、深链接与控制台 | 目标 SDK、设备、编译或资源协议已通过 |

`python3 tools/check_docs.py` 是统一静态入口；扩展 JSON Schema 验证需要 Python jsonschema 包，缺依赖明确报告不具备该检查，不静默跳过。`python3 -m unittest discover -s tools/tests` 验证文档工具。HTML 通过 `tools/render_visuals.py` 生成，不手改输出。

人工语义审查继续必需。节点不相交不保证文字和连线可读，使用 DOM 替身验证脚本不等于浏览器渲染；未执行项在报告中保持未执行。

`node tools/tests/panorama_smoke.cjs` 使用隔离的 DOM 替身检查专题脚本的配置切换、任务映射、构建步骤、时序、节点键盘选择、主题和深链接。它不启动浏览器、不访问页面，也不测量字体与布局。

## 变更与公开发布

更新规范后同步任务、案例、展示数据和生成页；所有检查针对同一份文件摘要。报告给出逐文件修改与保留原因，历史审查记录保持原样。当前首页指向最新报告，不用相同“最终版”标题掩盖版本关系。

公开文档包包含 docs 内部链接所需文件。九组研究阅读版及更新前快照统一保存在 references/legacy-boundaries；校验不依赖顶层研究目录或作者机器路径。公开发布前仍核对历史材料的许可与内容。产品状态由正式实施与认证记录决定。

## 当前规范与历史材料

当前行为写入对应 architecture 文档；任务验收与 DEC 准入映射写入 implementation-plan.json；ADR 解释取舍，examples 仅示意输入，HTML 从目录生成。正文不累计“本轮新增/上次修复”的流水账；逐文件变化进入 reviews，主页只指向当前复核和归档索引。

旧报告、清单与检查 JSON 保留原始字节和当时结论，不回填新结果；通过[归档索引](../reviews/README.md)与现行规范区分。封存原文是可选追溯材料，不作为默认使用路径。研究阅读版允许按明确范围修订，但必须保留原输入快照，并同步来源路径、行号和摘要；原问题身份及公共映射不得静默改变。删除规范前必须检查职责、任务、案例与链接是否已有明确承接，不以缩短文档为理由移除产品范围。

## 工程目录的单一维护入口

MadB 目录树只在 architecture/02-modules-and-ports.md 维护，MadB-Lab 目录树只在 validation/02-lab-architecture.md 维护。扩展和实施文档以链接及职责映射引用；architecture-overview.html 的目录区由生成器抽取这两份规范中的具名 text 块并转义输出。缺失、重复或格式不合法的目录块使生成失败。

目录是目标组织，实际源码是否存在、Cargo/原生构建是否通过、接口是否实现分别记录。目录规范和 HTML 通过不提升 C01 或其他工作包状态。保持设计基线 0.9，目录细化的变化与实际检查在独立审查记录中追溯。

## 研究阅读版与封存输入

研究阅读版修订后，静态检查同时验证来源文件摘要、问题编号/标题与行号，以及封存 ZIP 的文件清单和摘要；新旧 source_id 与公共问题映射必须一致。ZIP 只读取核验，不解压执行其中内容。需要改变问题含义或归并关系时另作明确决定，不能通过更新摘要掩盖范围变化。
