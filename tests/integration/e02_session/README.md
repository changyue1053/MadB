# E02 真实进程会话检查

本片复用现有 v1 wire 和端口 payload；宿主策略为每组件、每进程一个请求。
公开作者支持位于 `madb_protocol::extension_author`，示例助手只依赖 protocol/std；
CLI example 是测试组合根，不增加产品 CLI 命令。

```sh
cargo build --locked -p madb-protocol --example extension_peer -p madb-cli --example extension_session_probe --example extension_chain_probe
python3 -B -m unittest discover -s tests/integration/e02_session
```

Python 使用仓库 `.python-version` 规定的版本；本套测试只用标准库，现有开发环境也可用 `.venv/bin/python` 执行。可设置 `CARGO_TARGET_DIR` 隔离构建；测试使用同一目录寻找三个二进制。每次测试输出留在独立临时目录，包含实际进程报告与冻结文件；不会写源目录或修改历史证据。

检查真实 hello→ack→invoke→result 次序、身份和冻结版本、能力越界、恶意帧、重复终态、异常退出、握手/运行/结束预算、取消/完成竞争、取消握手后迟到 ack、诊断来源、进程组及管道清理。终态到达时先捕获未准入输出，进程退出和清理后重新核对该快照，再在取消原子准入内允许上游传递。

宿主文件读取和终态观察回调为同步操作，超时不能抢占正在执行的回调。返回后必须先复核原阶段与全局截止，再转入结束阶段；最终结果接受前再次核对。真实助手发送终态即退出、宿主故意延迟观察的案例分别证明阶段和全局超期均不能准入；这不承诺阻塞文件系统的硬墙钟中断。

普通测试启动/任务预算各 10 秒、总预算 30 秒，用于容纳隔离助手复制和受检启动的环境波动；专门超时负例仍使用原先 200 毫秒阶段预算及 3 秒全局预算。输出拒绝负例必须实际观察到 result，并匹配 OutputInvalid 或业务失败的 ToolFailed；较早超时不能替代该检查的目标证据。

固定两组件案例使用独立组件身份、进程和工作域；第一组件仅传递原子准入后的冻结字节。全部必需会话完成后才调用既有 LocalBatchStore 提交一个 build 批次；上游失败、下游失败/取消/迟到写入和提交取消均检查当前索引保持原值。它验证既有会话与事务接缝，不构成 E03 的路由、依赖、逐阶段责任或 ArkTS 普通/增强/替代配置实现。

BuildEvidence 和组合存储身份是独立定义的协议测试数据，助手没有执行编译器，不能作为 SDK、平台编译或公开制品验收。对完整业务结果的身份/文件域校验复用既有 payload 实现。终态观察能拒绝捕获后字节变化和观察时尚不存在的文件；同字节重写及宿主接收终态前发生的写入没有可证明的因果顺序。进程组不是系统安全沙箱；无法确认的派生工作必须保留缺口，不能解释为原生 SDK 已停止。
